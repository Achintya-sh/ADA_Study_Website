Contest readiness

Big idea

By now you know the algorithms. Contest marks are lost to things around the algorithm: choosing the wrong one, a Python slip, an edge case, or running out of clock. This stop is the final checklist: constraints that tell you the algorithm, the Python pitfalls that cost marks, one sheet of templates to type from memory, how to explain a solution out loud for the Mock AI Interview, and a full three-hour mock contest with answers.

1. Constraints tell you the algorithm

Python manages roughly 10⁷ simple operations per second. Read the largest input size n first.

The quiz at the end of this stop asks for the algorithm from the constraints alone.

2. Python pitfalls that cost marks

The function below demonstrates five of them with the values you will see (shown in the comments). The rest are in the list underneath.

  • Recursion limit. Python allows about 1,000 nested calls. DFS on a long chain, a skewed tree, or a deep memoised DP crashes. Write the iterative version (stacks, topological peeling) or convert to a table. Raising the limit with sys.setrecursionlimit may still overflow the real stack.
  • Slow input. For 10⁵ numbers use sys.stdin.readline or read everything once (template in stop 14).
  • Costly operations. list.pop(0) and x in list are O(n): use deque and set. s += c in a loop and slices like a[i:] copy; use indices.
  • heapq. A min-heap only (negate for max); tuples compare element by element, so a tie on the first value compares the second and may fail on objects that cannot be compared; there is no decrease-key, so push a new entry and skip stale ones.
  • Integer division and modulo round toward −∞, not toward zero.
  • Floats. Compare with a tolerance, or work in integers.

4. Explain it out loud (Mock AI Interview, 10%)

The interview asks conceptual questions and hands-on coding. For every algorithm you can code, be able to say four things in under a minute: what it does, the invariant (what stays true each step), the complexity and why, and the edge cases you would test. Then dry-run it on a three-element input.

A model answer: “Explain Dijkstra”

“Dijkstra finds shortest paths from one source when no edge is negative. I keep a min-heap of (distance, vertex). I pop the smallest; if it is stale I skip it; otherwise its distance is final, because any other route must go through a vertex still in the heap whose distance is at least as large, and edges cannot make it smaller. I then relax its edges and push improvements. Each edge causes at most one push, so the cost is O((V + E) log V). I would test an unreachable vertex, a graph with one vertex, and two equal-length paths. With a negative edge the finality claim breaks, so I would use Bellman–Ford.”

5. A full three-hour mock contest

Six problems in ADA proportions (heaps, trees, backtracking, Graphs II, DP-II, one hard). 180 minutes, 480 marks. Rules: read all six first (10 minutes); for each, write the brute force and submit it before looking for the trick (this is how Chakravyuh’s first subtask would have scored); never leave a problem at zero. Do not open the answers until the clock ends. Statements are summarised in my own words; open the link for the real one.

Answers (open after the clock ends)

Q1. A max-heap by negation; pop two, push the difference if non-zero. O(n log n).

Q2. Pass lower and upper bounds down the tree (comparing only with the parent is the classic wrong answer), or check that an inorder walk is strictly increasing. O(n). Code: is_bst in stop 4.

Q3. Precompute which substrings are palindromes (an n × n table), then backtrack over cut points, choosing a palindromic prefix and recursing on the rest. Exponential in the worst case (2ⁿ⁻¹ cuts), which is fine for n ≤ 16. Code: palindrome_partitions in stop 6.

Q4. Dijkstra with max(d, step) in place of d + step, or binary search the limit with BFS as the check. Compare both. O(RC log RC). Code: stop 12 section 2.

Q5. dp[i][j]: do s1[:i] and s2[:j] weave into s3[:i + j]? Return False at once if the lengths do not add up. O(nm). Code: interleave_table and interleave_row in stop 10.

Q6. Kahn’s algorithm; per vertex, a 26-entry list of the best colour counts on any path ending there; push it forward along edges; if fewer than n vertices are peeled, return −1. O((V + E)·26). Code: stop 12 section 1.

Marking. Full marks for an accepted solution; about half for a brute force that passes small tests. If Q3, Q5 or Q6 scored zero, re-do them from a blank file tomorrow and add the trap you hit to My mistakes.

Exam traps

Starting to code before reading the constraints. Trusting a template without running it on a tiny case and an empty case. Spending forty minutes on the hard problem while an easier one sits at zero. Forgetting that a brute force earns marks. Recursion on a deep structure. Not copying a list before saving it.

Remember

Read constraints → pick the cost class → pick the algorithm. Brute force first, submit, then optimise. Say invariant, cost, edge cases, dry run. Type the thirteen templates from memory.
