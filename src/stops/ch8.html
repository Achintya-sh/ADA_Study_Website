Graph traversal: DFS and BFS

Big idea

Two ways to visit every vertex reachable from a start. DFS dives deep and backs out; BFS spreads outward one layer at a time. They differ in exactly one data structure.

The problem: visit everything, once

In a tree, recursing into children just works. In a graph, a cycle would send you round forever. The cure: keep a visited[] array and never enter a vertex twice. Everything else is detail.

Traversal in plain words

A graph traversal is a systematic way of visiting every vertex reachable from a starting vertex, exactly once. Both algorithms below follow the same four-line idea; they differ only in which discovered vertex they continue from.

  1. Mark the start vertex as visited and put it in a "to do" container.
  2. Take one vertex out of the container.
  3. For each neighbour of it that is not visited yet, mark it visited and put it in the container.
  4. Repeat steps 2 and 3 until the container is empty.
If the container is a…The next vertex taken is…You get
Stack (last in, first out)the most recently discoveredDFS: dives deep before backtracking
Queue (first in, first out)the earliest discoveredBFS: widens one level at a time

If you need a refresher on stacks and queues, see chapter 0; the lab there lets you push, pop, enqueue and dequeue.

Remember

Three states of a vertex. Undiscovered (never seen), discovered (seen, waiting or in progress), finished (all its neighbours dealt with). CLRS names them white, gray and black; the lab uses the same colours.

Part A: Depth-First Search (DFS)

Teacher's note

Delivery-boy analogy. You enter a lane, deliver to a house, and immediately go down the next lane you can see, and the next, as deep as it goes. When you are stuck (nothing new reachable), you return to the last junction that still has an unexplored lane and go down that one. When nothing is left anywhere, you are done. "Go deep, then backtrack" is exactly the backtracking from chapter 6.

The recursion is the stack: each active call is a vertex you came through, and returning is backtracking. You can also use an explicit stack:

Complexity

Time O(V + E): each vertex is entered once (because of visited), and each vertex's adjacency list is scanned once, so every edge is examined once (directed) or twice (undirected). Space O(V): the visited array plus a recursion stack up to V deep (a long path).

Exam trap

With an adjacency matrix, finding a vertex's neighbours costs O(V), so DFS/BFS cost O(V²). "O(V+E)" assumes adjacency lists.

Connected components

On an undirected graph, dfs(0) visits exactly the component containing 0. Starting a new DFS from each still-unvisited vertex finds every component; the number of fresh starts is the number of components (see dfs_all). On a directed graph, dfs(0) only reaches what is reachable from 0.

What DFS can tell you (CLRS 22.3)

Remember

Facts to remember. In an undirected graph DFS produces only tree edges and back edges. A directed graph has a cycle if and only if DFS finds a back edge. Run the lab below and watch edges change colour as they are classified.

Added: missing from your notes

Topological sort (a famous DFS application). For a DAG, list vertices so that every edge u→v has u before v (think: course prerequisites). Run DFS, and as each vertex finishes, put it at the front of a list. Reason: with no back edges, v always finishes before u for an edge u→v, so u ends up ahead of v. Time Θ(V+E).

Part B: Breadth-First Search (BFS)

Teacher's note

Ripple analogy. Drop a stone in a pond: the ripple reaches everything at distance 1, then everything at distance 2, and so on. BFS visits the start, then all its neighbours, then all of their new neighbours: level by level. Level-order traversal of a tree is BFS.

The tool is a queue (first in, first out). Vertices are processed in the order they were discovered, which is exactly what produces the level-by-level pattern.

Exam trap

Mark a vertex visited when you add it to the queue, not when you remove it. If you wait until removal, a vertex reachable by two different neighbours is queued twice, which wastes time and (in distance computation) can corrupt answers.

BFS finds shortest paths (unweighted graphs)

BFS reaches vertices in non-decreasing order of distance. The first time it discovers v, it did so through some u at distance d, so v is at distance d + 1, and no shorter route exists (otherwise v would have been discovered earlier). CLRS proves v.d = δ(s, v), the true shortest number of edges. Record the distance when enqueuing; record the parent to rebuild the path.

Added: missing from your notes

Weighted graphs: BFS counts edges, not weights, so it is wrong for weighted shortest paths. Those use Dijkstra's algorithm, which is BFS with the queue replaced by a priority queue (a heap, chapter 5). A neat bridge between chapters.

Classic: Rotting oranges (multi-source BFS)

Grid: 0 empty, 1 fresh, 2 rotten. Each minute, every fresh orange next to a rotten one becomes rotten. Find the minutes until no fresh remain, or −1 if impossible. Idea: put all rotten oranges in the queue at time 0 (several starting points at once), then each BFS level is one minute.

Common mistakes with traversals

  • No visited array on a graph that has a cycle: infinite loop or stack overflow.
  • BFS: marking visited at dequeue time instead of at enqueue time: duplicates in the queue.
  • Forgetting disconnected graphs: starting once misses other components. Loop over all vertices and start from each unvisited one.
  • Using DFS for shortest paths: DFS finds a path, not the shortest one. Use BFS (unweighted) or Dijkstra (weighted).
  • Treating undirected edges as directed: when you build the adjacency list from an undirected edge (u, v), add v to u's list and u to v's list.
  • Wrong complexity: O(V + E) holds for adjacency lists; with a matrix it is O(V²).
  • Grid problems: forgetting the bounds check 0 <= r < R before reading grid[r][c].

Template 1: edges to adjacency list, iterative DFS

LeetCode almost always gives n and edges. Build the list (Graph 1), then traverse with an explicit stack (Graph 2). Marking a node when you push it means it is never pushed twice.

Solution: 2316 Count Unreachable Pairs of Nodes (1604). Try it first.

Two nodes are unreachable exactly when they're in different components. Walk through the component sizes and pair each component with everything counted before it, so no pair is counted twice.

Template 2: grid flood fill

A grid is a graph: each cell is a node, joined to its 4 neighbours (bridge 6.5). The neighbour loop with a bounds check is the whole trick.

Solution: 1020 Number of Enclaves (1615). Try it first.

Counting cells that can't escape is awkward. Flip it: everything connected to the border can escape, so sink all of those first, then count the land that's left.

Template 3: BFS shortest path

From Graph 3: in an unweighted graph BFS reaches every node by the fewest edges. Keep a dist array instead of visited: −1 means "not reached yet", and it stores the answer at the same time.

Solution: 1926 Nearest Exit from Entrance in Maze (1638). Try it first.

BFS from the entrance over open cells. The first border cell you reach (other than the entrance itself) is the nearest exit.

Template 4: multi-source BFS

Your Graph 3 lecture's rotting oranges is the model. When something spreads from many starting points at once, put all of them in the queue before the loop. Processing the queue one whole level at a time counts minutes (or distance) correctly.

Your mid-sem Q6: Signal Propagation at Time K

Several devices have the signal at t = 0; each second it spreads to every neighbour that doesn't have it yet. Count the devices first reached at exactly time k. That is multi-source BFS: put every source in the queue at distance 0, then count distances equal to k.

Template 5: direction tricks

Solution: 1466 Reorder Routes to Make All Paths Lead to the City Zero (1634). Try it first.

Treat the roads as undirected so you can walk the whole tree from city 0, but remember each road's real direction. Every road you walk away from 0 in its original direction must be flipped.

And the shortest one on the ladder: in 1557 Minimum Number of Vertices to Reach All Nodes (1512) the graph has no cycles, so the answer is just every node with in-degree 0, because nothing else can reach them and they reach everything else. No traversal at all: read the statement for structure before reaching for BFS.

Exam traps

Marking visited when you pop instead of when you push lets a node enter the queue several times: correct answers, but time limits on big grids. Forgetting to return −1 when something is unreachable. Counting one minute too many in multi-source BFS (count a minute only while fresh oranges remain). Using recursion on a large grid.

Remember
  • Decide what a node is and what an edge is; the rest is a template.
  • Components: DFS from every unvisited node. Border flood: sink the border first.
  • Fewest steps, equal costs: BFS with a dist array. Many sources: put all of them in the queue first.
  • Mark on push. Use a stack or deque, not recursion, on big inputs. O(V + E), or O(R · C) on a grid.

Pattern 8: functional graphs (Chakravyuh)

The statement: a[i] is the node that i points to, or −1 for no edge. From each start v, follow edges as long as you can and count the distinct nodes you see, including v.

The observation. One way out of every node means the walk never branches. It runs in a straight line until it hits a dead end, or reaches a node it has already seen and would then loop forever. Draw it and you get a tail feeding into a cycle: the Greek letter ρ. Every piece of such a graph is one cycle (or a dead end) with tails hanging off it. Three cases give the whole answer:

  • a node on a cycle of length L reaches exactly the L cycle nodes: answer L;
  • a node with a[v] = −1 reaches only itself: answer 1;
  • any other node reaches itself plus everything its successor reaches: answer 1 + ans[a[v]].

Subtask 1 (n ≤ 10³): the eight lines worth about half the marks

Walk from every node with a set of seen nodes. Each walk is at most n steps, so the total is n² = 10⁶. For n = 10⁵ it is 10¹⁰ and subtask 2 times out, but the points from subtask 1 are banked, and you now own a checker for the fast version.

Both versions were checked against each other on thousands of random graphs. chak_solve handles a 10⁵-long tail or cycle in a few hundredths of a second.

A second route: peel. Peel off every node with in-degree 0 (Kahn’s algorithm, stop 12). The survivors are exactly the cycle nodes; measure each cycle once, then go through the peeled nodes in reverse order, because each node’s successor was peeled after it.

Exam traps

The natural ans(v) = 1 + ans(a[v]) fails twice: on a cycle it never reaches a base case, and on a 10⁵-long tail it passes Python’s recursion limit. Keep the walk in a list. A self-loop (a[v] = v) is a cycle of length 1. Check −1 before indexing, because a[-1] silently reads the last element.

Relatives you should be able to write

Where does the cycle start? Floyd’s tortoise and hare finds the tail length and cycle length in O(n) time and O(1) extra memory, without a visited array.

Where am I after 10¹⁸ steps? Precompute the node reached after 1, 2, 4, 8, … steps and combine the bits of k (binary lifting): O(log k) per query. This is CSES Planets Queries I.

The mirror image. Given c[i], the number of nodes reachable from i, build any valid graph or say −1. A node with value 1 is a dead end. A node with value v ≥ 2 either hangs off a node of value v − 1 (a tail), or, if no such node exists, belongs to a cycle of length v, so the count of such nodes must be a multiple of v. Checked against every possible graph for n ≤ 5.

Two more functional-graph facts that decide problems: every connected component has exactly one cycle, and “fix the graph so it is a tree” (CF 698B, Ladder) means exactly one edge change per cycle.

Pattern 9: bipartite and two-colouring

“Split into two groups so no pair in a group is connected”, “no odd cycle”, “teams”: BFS with colours 0 and 1. If an edge joins two nodes of the same colour, an odd cycle exists and the answer is no.

Pattern 10: the node is a state

When the rule depends on more than where you are (parity of steps so far, how many passes you have used), make the pair the node. “Shortest odd-length walk”: nodes (vertex, parity), and each edge flips the parity. The BFS is unchanged; only the visited array is twice as big. Checked against listing every walk length up to 2n + 2.

The same idea with weights is in stop 12 (free passes: node = (vertex, passes used)).

Remember

Out-degree ≤ 1 → ρ shapes: cycle nodes get L, dead ends 1, everything else 1 + ans[next].

Read the subtasks: n ≤ 10³ allows a walk from every node. Submit it first.

Extra condition (parity, passes used, colour) → make it part of the node.
