Dynamic Programming II: two-dimensional tables

Big idea

When one index cannot describe a subproblem, the table grows a second dimension. The recipe from chapter 9 is unchanged; the state is now a pair, dp[i][j]. We build it up with grid paths, Longest Common Subsequence and the 0/1 Knapsack.

Start here: why one index is not enough

In chapter 9 a subproblem was identified by one number: "the first i steps", "the first i houses". Many problems have two things that shrink at the same time:

  • comparing two strings: how much of the first string and how much of the second are still in play;
  • walking on a grid: which row and which column you are standing on;
  • packing a bag: how many items you have looked at and how much capacity is left.

The question to ask is the same as always: "What do I need to know to continue from here, and nothing more?" If the honest answer is two numbers, those two numbers are your state, and the table is a rectangle with one row per value of the first and one column per value of the second.

Remember

Counting rule for running time: time = (number of cells) × (work per cell). Each cell in these problems does O(1) work (a max, a min, a sum of two neighbours), so the time is just the size of the table. Space is also the size of the table, unless you keep only the rows you still need.

The recipe, now with two indices

  1. State. Say in one sentence what dp[i][j] means. Be exact about whether i counts items (1-based) or points to a position (0-based).
  2. Last choice. Look at the final decision for that state. Each option leads to a smaller state.
  3. Transition. Combine the smaller states with max, min or +.
  4. Base cases. An entire row and column of the table are usually base cases (empty string, zero items, zero capacity, the edge of the grid).
  5. Order. Fill so that every cell is computed after the cells it reads. Almost always: row by row, left to right.
  6. Answer. Usually the bottom-right cell.
Which cells does dp[i][j] usually read?

                col j-1            col j
   row i-1   dp[i-1][j-1]       dp[i-1][j]
   row i     dp[i][j-1]         dp[i][j]   <-- computed last

Row-by-row, left-to-right order guarantees all three neighbours are ready.

Classic 1: minimum-cost path on a grid

Worked example

Problem. An m × n grid holds a cost in every cell. Start at the top-left, finish at the bottom-right, moving only right or down. Find the smallest total cost of a route. Example: [[1,3,1],[1,5,1],[4,2,1]] → 7 (route 1 → 3 → 1 → 1 → 1).

  1. State: dp[i][j] = the cheapest cost of any route from (0,0) to cell (i, j), including the cost of (i, j) itself.
  2. Last choice: you arrived at (i, j) either from the cell above, (i−1, j), or from the cell on the left, (i, j−1). Nothing else is possible, because you only move right or down.
  3. Transition: dp[i][j] = grid[i][j] + min( dp[i−1][j], dp[i][j−1] ).
  4. Base: dp[0][0] = grid[0][0]. The first row can only be reached from the left, the first column only from above.
  5. Order / answer: row by row; answer = dp[m−1][n−1].
Exam trap

Two Python traps in grid DP. (1) [[0] * n] * m does not make m separate rows; it makes m references to the same row, so writing one cell changes a whole column. Always write [[0] * n for _ in range(m)]. (2) dp[i-1][j] when i = 0 does not crash: index −1 silently reads the last row. That is why the first row and column are handled separately above.

Greedy fails here too. "Always step to the cheaper neighbour" ignores what lies beyond that neighbour. Try the Greedy trap grid in the lab: greedy pays 13, DP finds 10.

Classic 2: Longest Common Subsequence (LCS)

Worked example

Problem. A subsequence keeps the original order but may skip letters ("ACE" is a subsequence of "ABCDE"). Given strings X and Y, find the length of the longest string that is a subsequence of both. Example: X = ABCBDAB, Y = BDCABA → 4 (for instance BCBA).

Deriving the recurrence from scratch. Let c[i][j] be the LCS length of the first i letters of X and the first j letters of Y. Look only at the last letters, X[i] and Y[j] (1-based):

  • They are equal. That letter can end the common subsequence, so take it and solve for both strings shortened by one letter: c[i][j] = c[i−1][j−1] + 1. (Matching them is never worse than not matching.)
  • They differ. They cannot both be the final letter of a common subsequence, so at least one is unused. Drop X's last letter or Y's last letter and keep the better: c[i][j] = max( c[i−1][j], c[i][j−1] ).
  1. State: c[i][j] = LCS length of X[1..i] and Y[1..j].
  2. Base: c[0][j] = c[i][0] = 0 (an empty string has nothing in common with anything).
  3. Order / answer: row by row; answer = c[m][n].
  4. Rebuilding the string: start at (m, n). If the two letters are equal, record the letter and move diagonally. Otherwise move to the larger of the cell above and the cell on the left. Reverse what you recorded.
Exam trap

Off-by-one: the table is (m+1) × (n+1) because it has a row and column for the empty prefix, but the strings are 0-based. So cell (i, j) compares x[i-1] with y[j-1]. Subsequence vs substring: a substring must be contiguous. For the longest common substring, a mismatch resets the cell to 0 and the answer is the largest cell anywhere in the table, not the corner.

An LCS is not always unique (ABCBDAB and BDCABA have several of length 4). The traceback picks one depending on how ties are broken, but the length is always the same.

Classic 3: 0/1 Knapsack

Worked example

Problem. You have n items; item k has weight w[k] and value v[k]. A bag holds total weight at most W. Each item is taken whole or not at all (0 or 1 copies). Maximise the total value. Example: weights [1, 3, 4, 5], values [1, 4, 5, 7], W = 7 → 9 (the items of weight 3 and 4).

  1. State: dp[i][c] = the best total value using only the first i items with a bag of capacity c. Two things matter for the future: which items are still undecided (i) and how much room is left (c).
  2. Last choice: for item i, either skip it (the best is dp[i−1][c]) or take it, which is only possible if w[i] ≤ c, and then you earn v[i] plus the best for the first i−1 items in the reduced capacity c − w[i].
  3. Transition: dp[i][c] = max( dp[i−1][c], dp[i−1][c − w[i]] + v[i] ), where the second option exists only when w[i] ≤ c.
  4. Base: dp[0][c] = 0 (no items) and dp[i][0] = 0 (no room).
  5. Order / answer: row by row; answer = dp[n][W]. Items taken are rebuilt by walking back: if dp[i][c] equals dp[i−1][c], item i was skipped; otherwise it was taken and c drops by w[i].
VersionTimeSpaceCan rebuild the chosen items?
Full 2D tableO(nW)O(nW)Yes (walk back through the table)
Rolling 1D arrayO(nW)O(W)Not directly; the earlier rows are gone
Exam trap

1. In the 1D version the capacity loop must run downward. Running it upward lets item i be counted again in the same pass, which solves the unbounded knapsack (unlimited copies) instead. 2. O(nW) is pseudo-polynomial: W is a number, and the size of the input is only about log W bits. If W doubles in value the work doubles, but the input barely grew. The knapsack problem is NP-hard in general. 3. "Take the best value/weight ratio first" (greedy) is wrong for 0/1 knapsack; it is right only for the fractional version where items can be cut. The lab's last frame shows the greedy answer next to the DP answer.

Saving space: the rolling row

Every cell in these tables reads only the previous row (and the current row to its left). So you can keep just two rows, or even one, and cut the space from O(mn) to O(n). For LCS this gives O(min(m, n)) space for the length. The price: you can no longer walk back to recover the actual string or item set, because the old rows were thrown away. If a question asks for the solution itself and not only its value, keep the full table.

Variations and next problems

Added: missing from your notes
  • Unique paths with obstacles: same as grid counting, but an obstacle cell has dp = 0.
  • Edit distance (CLRS): d[i][j] = d[i−1][j−1] if xᵢ = yⱼ; otherwise 1 + min( d[i−1][j] (delete), d[i][j−1] (insert), d[i−1][j−1] (replace) ). Base: d[i][0] = i and d[0][j] = j. O(mn).
  • Longest palindromic subsequence: LCS of the string with its own reverse.
  • Subset sum / partition: knapsack with a true/false table: dp[i][c] = dp[i−1][c] or dp[i−1][c − w[i]].
  • Coin change (fewest coins): dp[c] = 1 + min over coins of dp[c − coin]. One index only, so it is 1D, but it looks like knapsack.
  • Matrix-chain multiplication (CLRS): a table over ranges (i, j); each cell tries every split point k, so O(n³). It fills by increasing range length, not row by row.

Common mistakes

  • Not defining what dp[i][j] means, in particular whether i is a count (1-based) or an index (0-based).
  • A table of size m × n when the empty-prefix row and column need (m+1) × (n+1).
  • Forgetting that a fresh row must copy the "skip" option before testing the "take" option.
  • Filling in an order that reads a cell before it is computed.
  • Building the table with [[0] * n] * m (shared rows).
  • Reporting dp[m][n] when the question wants the solution (string, item list, route); you also need the traceback.

Frog Jump, the way your lecture did it

A frog starts on stone 0 and wants to reach the last stone. From stone i it can jump to i + 1 or i + 2, and a jump costs the difference in heights, |h[i] − h[j]|. Find the minimum total cost.

f(i) = the minimum cost to reach stone i from stone 0. The last jump into i came from i − 1 or from i − 2:

f(i) = min( f(i−1) + |h[i] − h[i−1]|, f(i−2) + |h[i] − h[i−2]| ), f(0) = 0

  • Take/skip with a forced skip: fill from the back.
  • Counting: add the ways, mod every time. Huge values as states: use a dictionary.
  • Big n: bottom-up, not deep recursion.

The rule behind step 3 is the rule behind the lab: a cell may be overwritten only after every cell that still needs its old value has read it. Here reads go to smaller c, so the sweep goes downward.

Pattern 9: longest increasing subsequence, in O(n log n)

“Longest increasing subsequence”, “fewest piles”, “nested envelopes”. Keep tails[i], the smallest possible last value of an increasing run of length i + 1. That list stays sorted, so each new value replaces the first tail that is not smaller, found with bisect.

Pattern 10: two strings, one row

“Make s into t with insert, delete, replace”: dp[i][j] is the answer for the first i and first j characters, and each cell reads three neighbours. Only the previous row is needed.

Pattern 11: states instead of a table

When each day (or step) is in one of a few modes, keep one number per mode and update them together. Stock with a cooldown: holding, just sold, free to buy.

Pattern 12: bitmask DP (n ≤ 15)

“Assign n people to n jobs”, “visit every city once”: a bit per item that has been used, dp[mask] the best so far. 2ⁿ·n work, so only for n up to about 15–20.

Exam traps

The wrong loop direction silently turns 0/1 into unbounded. The wrong loop order turns combinations into orderings. For “exactly T”, unreachable sums need −1 or ∞, not 0. With an all-zero start, dp[W] means “capacity at most W”; for “exactly W” start from −∞ everywhere except dp[0] = 0. mask.bit_count() needs Python 3.10; otherwise bin(mask).count("1").

Knapsack = one row over capacity, filled item by item. Downward: once. Upward: unlimited. Bounded: downward, try each copy count.

Combinations: coins outside. Orderings: amount outside.

Memo → table (fill in dependency order) → one row (overwrite only after the last read).

LIS: bisect into tails. Two strings: dp[i][j] on prefixes. Few modes: one number per mode.

Memo → table → one row: three full conversions

Your end-sem question may hand you a memoised solution and ask for the table, or the table and ask for one row. The conversion is mechanical. Four steps:

  1. Recursion. Define f(i, j) in words (“the LCS of a[i:] and b[j:]”) and write it with base cases.
  2. Memo. Cache f. Same cells, same answers; only the repeated work disappears.
  3. Table. Allocate every (i, j). Read the arrows: if a cell needs (i + 1, j), (i, j + 1) and (i + 1, j + 1), those must be filled first, so loop backwards. If it needs (i − 1, j) and (i, j − 1), loop forwards. Base cases become the border row and column.
  4. One row. If row i only reads row i + 1 (or i − 1), keep a single list. The cell diagonal to you gets overwritten before you need it, so save it in a variable first.

Conversion 3: Interleaving String (LC 97), filled forwards

Can s3 be woven from s1 and s2, each keeping its own order? State: dp[i][j] = the first i letters of s1 and the first j of s2 weave into the first i + j of s3. A cell reads the cell above (use s1[i − 1]) or to the left (use s2[j − 1]), so the loops run forwards and the row version needs no diagonal at all. The first column has no left neighbour, which is the special case in the code.

Convert-this-code drills

  1. Close the page and write lcs_table from lcs_memo. Which way do the loops run, and why?
    AnswerBackwards in both i and j, because f(i, j) calls f(i + 1, …) and f(…, j + 1): those cells must exist first.
  2. Why does lcs_row need diag but a one-row coin-change table does not?
    AnswerThe LCS cell reads a diagonal neighbour, which the one-row update has already overwritten. The coin table only reads cells of its own row (and the previous values of the same cell), so nothing is lost.
  3. For minimum path sum on a grid (LC 64) a cell reads only the cell above and the cell to the left. Write the one-row version.
    AnswerInitialise row[0] and the first row by running sums; then for each later row set row[0] += g[i][0] and row[j] = min(row[j], row[j − 1]) + g[i][j]: row[j] is the cell above, row[j − 1] is the cell to the left. No diagonal, so no diag variable.
  4. In interleave_row, what breaks if you drop the j == 0 case?
    Answerrow[j − 1] would index −1 and read the last cell, silently mixing in the wrong value instead of raising an error.
