Master theorem on one card

T(n) = a·T(n/b) + f(n)        let c = log_b(a)      compare f(n) with n^c

f(n) polynomially smaller than n^c  →  T(n) = Θ(n^c)            leaves dominate
f(n) = Θ(n^c)                       →  T(n) = Θ(n^c · log n)    every level equal
f(n) polynomially larger than n^c   →  T(n) = Θ(f(n))           root dominates
                                        (and a·f(n/b) ≤ k·f(n), k < 1)
Gap (e.g. f = n^c · log n): theorem fails. Use a recursion tree.

Data structure rule cards

BST

Left < node < right at every node. Inorder is sorted. Cost O(h). Delete: leaf, one child, or two children (replace with inorder successor).

Heap

Complete tree + parent ≥ children (max). Array: children 2i+1, 2i+2; parent (i−1)//2. Insert = bubble up. Delete = swap root with last, sift down. Build = O(n).

Backtracking

Choose, explore, undo. Prune early. Copy before saving. Counts: n! permutations, 2ⁿ subsets.

Graph

Adjacency list for sparse graphs: O(V+E). Matrix: O(V²) space, O(1) edge test. Sum of degrees = 2E.

DFS / BFS

visited[] always. DFS = stack/recursion, finds cycles and components. BFS = queue, mark when enqueued, shortest path in unweighted graphs.

DP

State, choices, transition, base, order. Memo = recursion + cache. Naive Fibonacci-type recursion is exponential, DP makes it linear.

2D DP

State is a pair (i, j). Time = cells × work per cell. LCS: match → diagonal + 1, else max(up, left). Knapsack: max(skip, take); 1D version loops capacity downward. Keep the full table if you need the traceback.

Exam-writing tips

  • For "analyse the complexity", name the recurrence or the loop count first, then simplify. Marks are for the working.
  • For "dry run", draw a table with one row per step. Show the state after every step (array, stack, queue, visited).
  • State your assumptions: index base (0 or 1), duplicate policy, tree height convention, adjacency order.
  • Always say which case you are discussing: best, average or worst.
Added: missing from your notes

Corrections and clarifications to your lecture notes, collected in one place:
(1) BST operations are O(h), not O(log n), unless the tree is balanced. (2) The row "2T(n/2)+O(1) → BST ops → O(n)" in the quick-reference table really describes a full traversal. (3) Quick Sort's O(log n) space is an average; worst case O(n) unless you recurse into the smaller side first. (4) The notes' Master theorem has no "polynomially" or regularity condition; the gap case n log n exists. (5) DFS/BFS time O(V+E) assumes adjacency lists. (6) Heap build is O(n), not O(n log n). (7) Heap delete swaps with the larger child.

Model structure for long-answer questions

Question typeWhat to write, in order
"Explain algorithm X with an example"1. One-sentence idea. 2. Steps or pseudocode. 3. A small worked example as a table, state after every step. 4. Time and space complexity (best, average, worst). 5. One strength and one weakness.
"State and explain the rules of data structure Y"1. Definition. 2. Shape rule and order rule, with a small valid and invalid example. 3. How it is stored. 4. Each operation with cost. 5. When to use it.
"Analyse the complexity of this code / recurrence"1. Say what n is. 2. Count (loops multiply, sequence adds) or write the recurrence. 3. Solve (recursion tree or Master theorem, showing a, b, c and the case). 4. State Θ or O, and space.
"Compare X and Y"A table with the same rows for both: idea, time (best/avg/worst), space, when to prefer each.
"Trace / dry run"Table with one row per step; columns for the variables, data structure contents, and output so far.
"Design a solution for problem Z"Brute force and its cost, the observation that improves it, the chosen technique, pseudocode, dry run on the example, complexity.

Bridge essentials

0.5Trace one row per step. Code after a recursive call runs on the way back. Deepest stack = recursion space.
1.5f/g → 0: slower; → constant: Θ; → ∞: faster. logs < powers < exponentials < factorials. 4ⁿ is not O(2ⁿ). Induction: base, assume k, prove k + 1.
2.5Reader–writer partition: k ends the kept zone; grow k, then swap. Not stable. Three-way partition for duplicates.
3.5Mutating is shared, rebinding is local. Return and re-attach subtrees. Save nxt before turning an arrow.
4.50-based: children 2i + 1, 2i + 2; parent (i − 1) // 2. Height ⌊log₂ n⌋, leaves from index n // 2.
5.5kⁿ, 2ⁿ, n!, n!/(n − k)!, C(n, k). Brute force: 2ⁿ to n ≈ 25, n! to n ≈ 11. Record cur[:].
6.5At most n(n − 1)/2 undirected edges. [[0] * C for _ in range(R)]. Grid cell: up to 4 neighbours.
7.5Queue → BFS, stack → deep first. Visited set because of cycles. O(V + E).
8.5DP needs overlapping subproblems and optimal substructure. lru_cache needs hashable arguments. Greedy needs a proof.
9.5Table (m + 1) × (n + 1); dp[i][j] compares x[i − 1] and y[j − 1]; fill so sources come first.
10.5Counting is not listing. Fewest equal-cost steps → BFS. Best or count over overlapping choices → DP.
During the exam
  • Read every question first and note what each one asks for: a trace, a complexity argument, code, or a comparison.
  • For a dry run, draw the table before you start: one row per step, the whole state in every row.
  • Write the loop count or the recurrence before the answer. The working earns most of the marks.
  • Before handing in, scan for: 0-based indices, < versus <=, the pivot left out of both halves, the larger child in sift down, a copy before saving in backtracking, marking on enqueue in BFS.
