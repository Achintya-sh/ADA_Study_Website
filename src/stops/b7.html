One loop, two bags: the traversal template

Big idea

Every graph traversal is the same loop: take a vertex out of a bag, visit it, put its unvisited neighbours in. If the bag is a queue you get breadth-first search; if it is a stack you go deep first. You have already done both, on trees.

You have already traversed graphs

In stop 4, preorder went as deep as possible down the left before coming back: that is depth-first. Level order used a queue to visit the tree one level at a time: that is breadth-first. A tree is a graph with no cycles and exactly one path to each node, which is why those traversals never needed a visited list.

The template

Change one word and the search changes character. With popleft (queue, first in first out) the oldest discovery is handled next, so the search spreads out in rings. With pop (stack, last in first out) the newest discovery is handled next, so the search plunges deep.

Teacher's note

The stack version above goes deep first, but it does not always visit in the same order as recursive DFS, because it marks vertices when they are pushed rather than when they are visited. Both are valid depth-first behaviour. Stop 8 shows the iterative version that does match recursion exactly.

Why visited exists, and what it buys you

Graphs have cycles (0 → 1 → 4 → 2 → 0) and several paths to the same vertex. Without a visited set the bag never empties on a cycle, and even without cycles a vertex reachable in many ways is processed many times. With it, every vertex enters the bag once, so every adjacency list is scanned once. The scans add up to the sum of all degrees, which is 2E for an undirected graph. Total: O(V + E).

Recursion is a stack you don't see

Recursive DFS (stop 8) has no explicit bag. The call stack from bridge 0.5 is the bag: each pending call is a vertex waiting to continue. That is also why very deep recursive DFS can hit Python's recursion limit while the explicit-stack version cannot.

Why BFS finds shortest paths

BFS takes vertices out of the queue in order of distance from the start: first distance 0, then all of distance 1, then all of distance 2. At any moment the queue holds vertices from at most two neighbouring layers. So the first time BFS reaches a vertex, it has reached it with the fewest possible edges, as long as every edge costs the same.

Exam traps

In BFS, mark a vertex when you enqueue it, not when you dequeue it, or the same vertex can sit in the queue several times. Use deque.popleft(), not list.pop(0), which is O(n). BFS gives shortest paths only when all edges have equal cost.

Remember
  • Queue → BFS (rings outward). Stack → deep first. Same loop otherwise.
  • Trees need no visited set; graphs do (cycles, multiple paths).
  • Each vertex enters the bag once: O(V + E) with adjacency lists.
  • Recursion uses the call stack as its bag.
