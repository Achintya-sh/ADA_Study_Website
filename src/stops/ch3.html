Advanced sorting: Quick Sort

Big idea

The sort that skips the merge step. Learn partition until you can do it with your eyes closed; everything else follows from it.

Sorting basics (read this first)

Sorting means rearranging a list into increasing (or decreasing) order. It is the most studied problem in computing because so many other tasks, like searching and merging, become easy once data is sorted.

Vocabulary

TermMeaning
Comparison sortLearns the order only by comparing pairs ("is a[i] ≤ a[j]?"). All sorts in this course are comparison sorts.
In-placeUses only O(1) extra memory beyond the array (swapping elements inside it). Quick Sort, heap sort, insertion sort are in-place. Merge sort is not.
StableEqual keys keep their original relative order. Matters when sorting records, e.g. sorting students by grade after sorting them by name. Merge and insertion sort are stable; Quick Sort and heap sort are not.

PartitionRearranging so everything ≤ pivot comes before it and everything > pivot after it.

Added: missing from your notes

Why O(n log n) is the best a comparison sort can do. With n distinct items there are n! possible orderings. Each comparison has two outcomes, so after k comparisons you can distinguish at most 2k orderings. To be able to tell all n! orderings apart you need 2k ≥ n!, so k ≥ log₂(n!) = Θ(n log n). No comparison-based sort can beat n log n in the worst case, so Merge Sort, Heap Sort and Quick Sort's average are all optimal up to constants.

The motivation

You already know sorts that cost O(n²) (bubble, insertion, selection) and Merge Sort at O(n log n). Merge Sort has one annoying cost: to merge two sorted halves it copies them into extra arrays, so it needs O(n) extra memory.

Quick Sort asks: can we split the array so that no merging is needed at all? Yes, if we split it so that everything in the left part is ≤ everything in the right part. Then sorting the left part and the right part separately automatically sorts the whole array. The work moves from the "combine" step (Merge Sort) to the "divide" step (Quick Sort).

Teacher's note

Picture 20 students who must line up by height. Pick one student as the pivot. Everyone shorter stands on the pivot's left, everyone taller on the right. The pivot is now standing in exactly the right place and never needs to move again. Now repeat inside the left group and inside the right group. When every group has one student, the whole line is sorted.

The rules

  1. Pick a pivot. In your course: the last element.
  2. Partition: rearrange so that all elements ≤ pivot come first, then the pivot, then all elements > pivot.
  3. The pivot is now in its final sorted position. Never touched again.
  4. Recurse on the left part and the right part.
  5. Base case: a part with 0 or 1 element is already sorted.

Partition, step by step

The naive way builds two new lists, smaller[] and greater[], using O(n) extra space (no better than Merge Sort). The in-place way (called Lomuto partition) uses two markers:

  • pos: the scanner. It walks from the left end to just before the pivot.
  • k: the boundary of the "≤ pivot" zone. It starts at lo−1 (the zone is empty) and always points at the last element of the zone.

For each element at pos: if it is ≤ pivot, grow the zone (k += 1) and swap it into the zone. If it is bigger, leave it alone: it automatically becomes part of the "> pivot" zone sitting between k and pos. At the end, swap the pivot into position k+1, right between the two zones.

How fast is it?

Worst case: Θ(n²)

If the pivot is always the smallest or largest element, partition splits n elements into 0 and n−1. Recurrence: T(n) = T(n−1) + Θ(n), which unrolls to n + (n−1) + … + 1 = Θ(n²). With the last-element pivot, this happens on already sorted or reverse sorted input: the pivot is the maximum every time. It also happens when all elements are equal (every element is ≤ pivot, so k runs all the way to hi−1).

Best case: Θ(n log n)

If the pivot is always the median, each side gets n/2. Recurrence T(n) = 2T(n/2) + Θ(n), the same as Merge Sort → Θ(n log n) by Master theorem case 2.

Average case: Θ(n log n)

You do not need a perfect split. Any split in constant proportion keeps the tree logarithmic. Take a terrible 1 : 9 split: T(n) = T(n/10) + T(9n/10) + cn. The deepest path shrinks by a factor of 9/10 each step, so its length is log10/9n = O(log n). Every level costs at most cn. Total ≤ cn × O(log n) = O(n log n). Only splits like 0 : n−1 (constant difference, not proportion) are fatal.

Added: missing from your notes

The formal argument (CLRS 7.4). The running time is dominated by the number of comparisons. Let the elements in sorted order be z₁ … zₙ. Two elements zᵢ and zⱼ are compared at most once, and only if one of them is the first pivot chosen from the range {zᵢ, …, zⱼ}. With a random pivot that happens with probability 2/(j−i+1). Summing: Σᵢ Σⱼ 2/(j−i+1) = O(n log n), because the inner sum is a harmonic series.

Space and the stack

Partition is in-place (O(1)). But the recursion uses a stack: average depth O(log n), worst depth O(n) (the skewed case). A neat fix, not in your notes: after partitioning, recurse into the smaller side and loop on the larger side. The stack is then at most log n deep even in the worst case.

Randomized Quick Sort

An adversary (or just sorted data, which is very common) can feed the last-element rule its worst case. The cure: choose the pivot at random. Either swap a random element into the last position before partitioning, or shuffle the whole array first. No fixed input is bad any more; the expected time is Θ(n log n) for every input. The worst case still exists, but its probability is astronomically small.

Extras examiners like.

  • Pivot strategies: first, last, random, median-of-three (median of first, middle, last).
  • Not stable: equal elements can be reordered by the swaps. Merge Sort is stable.
  • In place (apart from the stack), unlike Merge Sort.
  • Many duplicates: this partition degrades to O(n²) on all-equal input. The fix is 3-way partition (less / equal / greater), used by real libraries.
  • Hoare partition is the older two-pointer scheme (pointers move inward from both ends); it does fewer swaps. What you have learned is the Lomuto scheme.
  • Quickselect: to find the k-th smallest element, partition once and recurse into only the side containing position k. Average O(n).

Exam trap

"Quick Sort is O(n log n)" is only the average claim. If a question says "worst-case time complexity of Quick Sort", the answer is O(n²). If it says "on a sorted array with the last element as pivot", the answer is also O(n²).

Patterns for contests: sorting

Seen in your contests

Contest 1 Q5 asked for Quick Sort in descending order and scored by test. The usual trap: with the last element as pivot, a reverse-sorted or all-equal array makes every partition peel off a single element. That is n² work and n levels of recursion. The fix is a random pivot, a three-way split so equal values are finished at once, and an explicit stack.

In a contest, use Python’s built-in sort (stable, O(n log n)). Write Quick Sort yourself only when the problem tells you to.

Quickselect is Quick Sort that follows only one side: after the split, the answer lies in exactly one of the three zones.

The merge step is the only place that changes: when an element of the right half is placed before the remaining left elements, it jumps over every one of them, and each jump is one inversion.

Exam traps

a.sort() returns None (use sorted(a) to keep the original). A comparison function needs cmp_to_key. Touching intervals [1,4] and [4,5] merge when the statement says “overlap or touch” and not when it says “share a point”. Lomuto partition with the last element as pivot is O(n²) on sorted input: say so in a written answer.

Remember

Sort first and the problem often becomes one pass. Out-of-order pairs: count while merging.

A fixed pivot loses to sorted input; a random pivot and a three-way split don’t.
