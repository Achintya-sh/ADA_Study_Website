Big idea

A monotonic stack keeps its contents in sorted order by popping everything that can no longer matter before pushing the new item. That one rule turns “for each element, find the nearest bigger/smaller one” from O(n²) into O(n): every element is pushed once and popped once. Your course outline lists monotonic stacks as a feature; this stop is where they live. The monotonic deque is the same idea with the front also expiring, for sliding windows.

Exam traps

Store indices, not values, when you need distances. Decide strict versus non-strict from the statement’s wording about equal values. Flush the stack at the end (a sentinel 0 in the histogram) or the last bars never get an answer. Pop in a while, not an if. Each element is pushed once and popped once, so the whole thing is O(n) even though there’s a loop inside a loop.

The routine for every problem

  1. Read the constraints and the subtasks before the story. Write down what each limit allows.
  2. Work one example by hand and restate the problem in one line using graph, DP or sorting words.
  3. Write the most obvious correct solution (simulate, try everything). Aim for about 10 minutes.
  4. Submit it. Marks are in the bank before you start thinking hard.
  5. Use it as a microscope: print its answers for tiny inputs and look for what repeats or stays fixed.
  6. Write the fast version, stress-test it against the brute force, then submit.

Speed. Local variables are faster than globals, so put the work inside a function. List comprehensions beat explicit loops. Lists of lists beat defaultdict(list) when keys are 0 to n − 1. Appending to a string with += in a loop is fine in CPython, but join a list when in doubt. Some judges run PyPy, which is much faster on plain loops but slower at some built-ins: use whichever interpreter the judge uses and test with it.

Hash-map attacks. On Codeforces some tests are built to make Python’s dict and set collide and slow to a crawl. If a hash-heavy solution times out for no visible reason, sort instead (bisect on a sorted list) or XOR the keys with a random 32-bit number before inserting.

Chakravyuh Reversed

Every node of a directed graph on nodes 0 … n−1 has at most one outgoing edge. You are told, for every node i, the number c[i] of distinct nodes reachable from i by following edges as long as possible, counting i itself. Print any array a (a[i] = −1 for no edge, otherwise the node i points to) that produces exactly this c, or print −1 if no graph does.

Subtask 1: n ≤ 6. Subtask 2: n ≤ 10⁵, 1 ≤ c[i] ≤ n.

Hints (one at a time)

1. What value does a node on a cycle of length L have? What value does a node hanging off one of them have, compared with its successor?

2. Count how many nodes hold each value v.

3. A node with value v ≥ 2 either points to a node with value v − 1, or lies on a cycle of exactly v nodes.

Subtask 1: the brute force{{code:rev_brute}}
The trick and the full solution

Group nodes by value. Value 1: dead ends. Value v ≥ 2: if any node has value v − 1, point every v-node at it; otherwise the v-nodes must form cycles of length v, so their count must be a multiple of v. The solution is reverse_chak in stop 8; it matched every possible graph for n ≤ 5.

Free Passes

n cities, m one-way roads with non-negative tolls. You hold k passes; each pass makes one road on your route free. What is the cheapest trip from city 0 to city n−1? Print −1 if there is no route.

Subtask 1: n ≤ 6, k ≤ 3. Subtask 2: n ≤ 10⁵, m ≤ 2·10⁵, k ≤ 10.

Hints

1. Where would you remember how many passes are left?

2. Draw k + 1 copies of the map. What does using a pass look like as an edge?

Subtask 1: the brute force{{code:free_brute}}
The trick and the full solution

Dijkstra on states (city, passes used): a normal edge stays in the same layer at its toll, a pass edge goes one layer down at cost 0. The answer is the best over all layers of city n−1. See min_cost_k_free in stop 12.

Subtask 1: the brute force{{code:visible_brute}}

Frozen Middle

A row of n cards holds a permutation of 0 … n−1. You may swap the cards at positions i and j only when |i − j| ≥ k. Using any number of legal swaps, can you sort the row into 0, 1, …, n−1?

Subtask 1: n ≤ 7. Subtask 2: n ≤ 2·10⁵.

Hints

1. Write the BFS for n ≤ 7 and print which rows are sortable for n = 5, k = 3. Look at what the unsortable ones have in common.

2. Which positions have no legal partner at all, whatever the other cards do?

Subtask 1: the brute force{{code:frozen}}
The trick

Position i can swap with j ≤ i − k or j ≥ i + k. Positions n − k … k − 1 have neither, so they are frozen: those cards must already be correct. Everything else is movable enough to be sorted. The one-line check sortable above matches the brute force on every permutation with n ≤ 6 and every k. Why the rest is always fixable is worth proving yourself.
