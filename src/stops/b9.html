Prefixes, subsequences and reading a 2D table

Big idea

Two-dimensional DP is mostly bookkeeping: what dp[i][j] means, which earlier cells it reads, and what order to fill the table in so those cells are ready. Most marks lost in stop 10 are off-by-one errors between string positions and table positions.

Substring, subsequence, subset

LCS is about subsequences, so there are 2ⁿ candidates in each string: brute force is hopeless and DP is the only sensible approach.

Prefixes and the extra row

x[:i] is the first i characters of x. i can be anything from 0 (the empty prefix "") to m, so a table indexed by prefix length needs m + 1 rows and n + 1 columns.

  • dp[i][j] answers the question for x[:i] and y[:j].
  • The newest characters in those prefixes are x[i − 1] and y[j − 1]: table index i, string index i − 1.
  • Row 0 and column 0 mean "one string is empty": these are the base cases, filled before the loops.

Dependency arrows decide the fill order

Draw an arrow from each cell to the cells its rule reads. Any fill order works as long as every arrow points to a cell already filled.

The answer is usually in the bottom-right cell dp[m][n], because that cell describes the full strings. Some variants (longest common substring) take the maximum over the whole table instead, so read the definition of the state before you read off an answer.

Exam traps

Comparing x[i] with y[j] inside a table loop that runs i from 1 to m reads one character too far (and crashes at i = m). A table of size m × n has no room for the empty prefixes. "Subsequence" in a question is not "substring".

Remember
  • Substring = contiguous; subsequence = in order with gaps; subset = order ignored.
  • Table (m + 1) × (n + 1). dp[i][j] is about x[:i] and y[:j] and compares x[i − 1] with y[j − 1].
  • Fill so every cell's sources are already filled.
