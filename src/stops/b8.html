Overlapping subproblems, caches and greedy choices

Big idea

Dynamic programming is recursion plus a memory. It pays off when the same smaller problem is solved again and again, and it is needed when the obvious "take the best-looking option now" strategy (greedy) can be wrong. Learn to spot both before stop 9.

Disjoint versus overlapping subproblems

Merge sort splits an array into two halves that share nothing, so no piece is ever sorted twice; remembering answers would not help. Fibonacci is the opposite: fib(n) calls fib(n − 1) and fib(n − 2), and fib(n − 1) calls fib(n − 2) again.

The number of calls grows like the Fibonacci numbers themselves (about 1.6ⁿ), while there are only n + 1 different questions being asked. Storing each answer the first time turns millions of calls into a few dozen. That gap is the whole reason DP exists.

Caches in Python

Added: missing from your notes

@lru_cache (or @cache in Python 3.9+) memoizes a function automatically. Its arguments must be hashable: numbers, strings and tuples work, lists do not (convert a list to a tuple first). It does not remove recursion depth, so for very large n a bottom-up loop is still safer.

Optimal substructure

DP also needs the best answer to be built from best answers of smaller problems. A shortest route from A to C through B contains a shortest route from A to B; if it didn't, you could swap in the shorter piece and beat it. Stop 9's recipe ("state, choices, transition, base, order") is a way of writing that property down.

Greedy: sometimes enough, sometimes a trap

A greedy algorithm makes the choice that looks best right now and never reconsiders. For making change with the fewest coins, "take the biggest coin that fits" works for coins 1, 5, 10, 25. Mathematicians call such coin systems canonical. For other systems it fails:

CoinsAmountGreedyBest
1, 3, 464 + 1 + 1 (3 coins)3 + 3 (2 coins)
1, 5, 6, 9119 + 1 + 1 (3 coins)5 + 6 (2 coins)
1, 7, 101410 + 1 + 1 + 1 + 1 (5 coins)7 + 7 (2 coins)

Greedy never considered skipping the big coin. DP tries every last coin for every amount, so it cannot be fooled. The rule for exams: a greedy algorithm needs a proof; one counterexample is enough to sink it.

Remember
  • Disjoint subproblems (merge sort): caching is useless. Overlapping (Fibonacci): caching is everything.
  • Memoize with a dict or @lru_cache; arguments must be hashable.
  • DP needs overlapping subproblems and optimal substructure.
  • Greedy is fast but needs a proof; disprove it with one counterexample.
