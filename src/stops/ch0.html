Memory in one page: variables, arrays, linked lists

Think of computer memory as a very long row of numbered boxes. A variable is a labelled box. Two ways of storing a collection of items:

Array (Python list)

Items sit in consecutive boxes. Because the boxes are side by side, the computer finds item number i by simple arithmetic: O(1) access by index. Inserting or deleting in the middle forces everything after it to shift: O(n). Appending to the end is O(1) (amortised).

Linked list

Each item is a small node holding a value and a pointer (the address) of the next node. Nodes can be anywhere in memory. Reaching item i means following i pointers: O(n). But inserting right after a node you already hold is O(1): just rewire two pointers.

Remember

A pointer (reference) is just "where to find another node". A tree node holds two pointers (left and right); a graph vertex holds a list of them. None means "no node there". This idea powers chapters 4 to 8.

Stack: last in, first out (LIFO)

A stack of plates: you put a plate on top and take the top one off. The last plate added is the first removed. Three operations, all O(1): push (add to top), pop (remove and return top), peek (look at top).

Where you will meet it: the recursion call stack (each active function call is a plate), DFS, undo buttons, matching brackets.

Queue: first in, first out (FIFO)

A line at a ticket counter: people join at the back and leave from the front. The first to arrive is the first served. Operations: enqueue (join at back), dequeue (leave from front), both O(1).

Where you will meet it: BFS, level-order tree traversal, scheduling.

Sets and dictionaries (hashing)

A set remembers which items it has seen. A dictionary maps a key to a value (name → phone number). Both answer "is this key present?" in about O(1) time on average, thanks to hashing (the key is turned into a position in a table). You will use a set or boolean array for visited and a dictionary for memo.

Trees at a glance

A tree stores hierarchical data: a folder containing folders, a family tree, a company chart. There is one top node, the root; every other node hangs below exactly one parent; nodes with nothing below are leaves. Chapter 4 builds this up carefully, from the rules to every operation.

Maths you need: powers, logarithms, sums

Powers of 2

Computing uses 2 constantly. Learn these: 2¹⁰ = 1,024 ≈ 10³ (a thousand), 2²⁰ ≈ 10⁶ (a million), 2³⁰ ≈ 10⁹ (a billion).

The logarithm: "how many times can I halve it?"

log₂ n (written lg n, or just log n in this course) is the answer to: how many times can I cut n in half before I reach 1? Equivalently, it is the power you raise 2 to in order to get n: 210 = 1024, so log₂ 1024 = 10.

log₂ n (about)34102030

This is why log n algorithms are astonishingly fast: a billion items need only about 30 steps. Binary search, balanced trees and heaps all get their speed from halving the problem each step, or from a tree whose height is log n.

Remember

Log rules you will use: log(a·b) = log a + log b. log(n²) = 2·log n. Changing the base only changes a constant: log₂n = log₁₀n / log₁₀2, so in Big-O we never write the base. And log_b(a) in the Master theorem means "the power of b that gives a"; for example log₃ 27 = 3 because 3³ = 27.

Floor and ceiling

⌊x⌋ rounds down (⌊3.7⌋ = 3). ⌈x⌉ rounds up (⌈3.2⌉ = 4). Heap parents use ⌊(i−1)/2⌋; a tree with n nodes needs a height of at least ⌈log₂(n+1)⌉ − 1.

Factorial

n! = n × (n−1) × … × 2 × 1, with 0! = 1. It counts the ways to arrange n distinct items: 3! = 6, 5! = 120, 10! = 3,628,800.

Teacher's note

Why n(n+1)/2? Write the numbers forwards and backwards and add column by column: (1+n) + (2+(n−1)) + … Each of the n columns sums to n+1, and we counted everything twice, so the total is n(n+1)/2. Pair the first with the last, the second with the second-to-last, and so on.

Exam trap

Creating a 2D grid: [[0]*n]*n is a classic bug. It makes n references to the same row. Use [[0]*n for _ in range(n)] to get n separate rows.
