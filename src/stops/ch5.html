Heaps and priority queues

Big idea

A structure built for one question: "who is the most important item right now?" Learn the two rules, the array trick, and the two moves (bubble up, sift down).

The problem a heap solves

A hospital emergency room needs three operations: add a patient, see who has the highest emergency score, and remove that patient. Let N be the number of waiting patients.

Designinsert(x)get_max()delete_max()Problem
Unsorted lineO(1)O(N)O(N)Must scan everyone to find the worst case
Sorted lineO(N)O(1)O(1)Insert must shift people to keep order
HeapO(log N)O(1)O(log N)Good at everything

The heap's trick is to keep just enough order: not fully sorted (expensive), only enough to know the maximum instantly.

Building the idea from scratch

  1. A sorted line is a path. What if we join many short sorted lines into a tree, so that every path from root down to a leaf is sorted?
  2. For every root-to-leaf path to be sorted (largest at top), each parent must be ≥ its children. This is the order property. Consequence: the maximum is at the root.
  3. For a fixed number of nodes, the shortest possible tree is one with every level full. That shape is a complete binary tree. Its height is about log₂N, so any root-to-leaf walk is short. This is the shape property.

The two rules

Remember

Max-heap = complete binary tree + every parent ≥ its children.
Min-heap = complete binary tree + every parent ≤ its children.

Exam trap

A heap is not a BST. In a heap, the left child is not required to be smaller than the right child. Siblings have no order. That is why searching for an arbitrary value in a heap is O(N), and why a heap cannot print sorted output by a simple inorder walk. A heap only promises: the top is the best.

Heap basics: the definition, rule by rule

Remember

Definition. A heap is a binary tree that satisfies two rules at once: a shape rule (it is a complete binary tree) and an order rule (every parent is ordered against its children). A max-heap requires parent ≥ child. A min-heap requires parent ≤ child.

Rule 1: the shape rule (complete binary tree)

Number the levels from the top: the root is level 0, its children level 1, and so on. A tree is complete when:

  1. Every level is completely full, except possibly the very last one.
  2. The last level is filled from left to right with no gaps.

Practical meaning: to add a node, you put it in the first free slot reading level by level, left to right. To remove a node, you remove the last one in that reading order. This is why heaps never get lopsided: their height is always about log₂ n.

Rule 2: the order rule

The order rule compares only a parent with its own children:

  • Max-heap: value(parent) ≥ value(each child). Consequently the largest value is at the root.
  • Min-heap: value(parent) ≤ value(each child). Consequently the smallest value is at the root.

Equal values are allowed (that is why we write ≥ and ≤). Crucially, siblings are not compared with each other, and a node is not compared with its cousins or with nodes in other branches.

Setup: storing a heap in an array

Because of the shape rule, the heap occupies positions 0, 1, 2, …, n−1 of an array with no gaps. The array is just the tree read level by level, left to right. To read an array as a heap: write the first element as the root, the next two as its children, the next four as the next level, and so on.

Storing a heap in an array (no pointers!)

Insert: bubble up (O(log n))

  1. Put the new value at the next free slot (end of the array). This keeps the shape rule.
  2. The order rule may now be broken between the new node and its parent. While the new node is bigger than its parent, swap them (move up one level).
  3. Stop when the parent is ≥ the node or you reach the root.

The node climbs at most one level per swap and there are about log₂n levels, so the cost is O(log n).

Worked example

Insert 9 into [15, 8, 10, 6, 3, 5, 7, 2, 1]. New slot is index 9, parent index 4 (value 3).

Delete max: sift down (O(log n))

The max is the root, so removing it leaves a hole at the top and breaks both rules. The repair is neat:

  1. Swap the root with the last node, then remove the last slot. Shape is fixed instantly (we removed the last position). The old max is gone.
  2. The new root is probably small and breaks the order. Sift down: compare it with its two children, swap it with the larger child, and repeat from there.
  3. Stop when it is ≥ both children, or it has none.
Exam trap

Swap with the larger child, not just any child. If you swap with the smaller child, that smaller child becomes the parent of the larger sibling and the order rule is broken again.

Worked example

Delete the max (15) from [15, 8, 10, 6, 3, 5, 7, 2, 1].

Build a heap from N items: O(N), not O(N log N)

Inserting N items one at a time costs O(N log N). There is a faster way: dump the array in as is, then fix it from the bottom up. Leaves are already valid one-node heaps, so start at the last non-leaf (index ⌊n/2⌋ − 1) and sift down each node, moving toward index 0.

Worked example

Build from [4, 10, 3, 5, 1]. n = 5, start at i = 1. Node 10 (children 5 and 1): already ≥ both, fine. Then i = 0: node 4 has children 10 and 3, swap with 10 → [10, 4, 3, 5, 1]; 4 now at index 1 with children 5 and 1, swap with 5 → [10, 5, 3, 4, 1]. Done: a valid max-heap in 2 swaps.

Added: missing from your notes

Why O(N)? (CLRS 6.3) Sifting a node costs O(its height), not O(log n). Half the nodes are leaves (height 0, free). A quarter have height 1, an eighth height 2, and so on. In general at most ⌈n/2h+1⌉ nodes have height h. Total = Σ over h of (n / 2h+1) · O(h) = O(n · Σ h/2h) = O(n), because the sum Σ h/2h converges to 2. Most nodes are near the bottom and travel only a short distance.

Heap sort

Build a max-heap in O(n). Then repeat: swap the root (largest) with the last unsorted position, shrink the heap by one, and sift down the new root. After n−1 rounds the array is sorted ascending. Time O(n log n) in all cases, space O(1), not stable.

Problem solving using heaps

Spot the pattern: "repeatedly take the smallest/largest", "top k", "merge sorted streams", "median of a stream".

1. The k-th largest element

Counter-intuitive: use a min-heap of size k. It always holds the k largest seen so far, and its top (the smallest of those k) is the k-th largest. Any new value smaller than the top cannot be among the k largest.

Worked example

nums = [3, 2, 1, 5, 6, 4], k = 2. Heap after each item: [3] → [2,3] → 1 is smaller than 2, ignore → 5 > 2, heap [3,5] → 6 > 3, heap [5,6] → 4 < 5, ignore. Top = 5, the 2nd largest. The heap holds the two largest: 5 and 6.

2. Running median (two heaps)

Keep the lower half of the numbers in a max-heap and the upper half in a min-heap, with sizes differing by at most 1. The median is at the top of one heap (or the average of both tops). Each insertion is O(log n), reading the median is O(1).

3. Merge k sorted lists

Put the first element of each list in a min-heap (with its list id). Pop the smallest, output it, push the next element from the same list. N total elements, heap size k → O(N log k).

4. Connect ropes at minimum cost

Cost of joining two ropes is the sum of their lengths. Greedy: always join the two shortest. Min-heap: pop two, push their sum, add the sum to the cost. O(n log n).

5. Other classics

  • Top k frequent elements: count with a dictionary, keep a size-k min-heap on counts.
  • Sort a nearly-sorted array (each element at most k places off): a min-heap of size k+1 gives O(n log k).
  • Task scheduling / CPU scheduling / Dijkstra's shortest path: all use a priority queue as the engine.
Teacher's note

Whenever a brute force keeps doing "scan everything to find the biggest/smallest", ask: can a heap hand me that in O(log n) instead of O(n)? That one question solves most heap problems.

Exam traps

heapq is a min-heap only: store negatives for a max-heap. Tuples compare left to right, so put the priority first and add an index as a tie-breaker if the second item can’t be compared. “Touching” meetings (end = next start) share a room when the check is <=. Sifting down: compare with both children and swap with the smaller one.

Remember

Heap = the best item now, in O(log n). Sort by when things become available, then pop the best.

No heapq allowed: array + bubble up + sift down, both O(log n).
