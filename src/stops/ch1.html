Problem-solving foundations

Big idea

Before any data structure: how to read a problem, choose a strategy, and know whether your idea is fast enough before you write a line of code.

What is an algorithm, really?

An algorithm is a finite, unambiguous list of steps that turns an input into a desired output. A recipe is an algorithm for cooking. "Look up a word by opening the dictionary in the middle, deciding which half the word is in, and repeating" is an algorithm for searching.

A data structure is a way of arranging data in memory so that certain operations are cheap. Arrays make "get the 5th item" cheap. Heaps make "get the biggest item" cheap. Trees make "find this key" cheap. Every algorithm in this course is really a pairing: a data structure plus a strategy for using it.

Teacher's note

When you meet any new topic in this course, ask three questions in order: (1) What rule does this structure enforce? (2) Which operations does that rule make fast? (3) What does keeping the rule cost on insert and delete? Every chapter below is organised around those three questions.

A repeatable approach for any problem

Exam questions and interview questions both reward a calm routine over inspiration. Use these six steps.

StepWhat you doTypical mistake it prevents
1. UnderstandRestate the problem. Write the input, the output, and the limits (how big can n be? can values repeat? can the input be empty?). Make one small example by hand.Solving a different problem from the one asked.
2. Brute forceDescribe the slowest correct solution, even if silly. State its time complexity.Having no answer at all. Also gives you a correctness checker.
3. Match a patternLook at the clue words (table below) and choose a technique: sort, heap, BST, BFS, DFS, backtracking, DP.Reinventing something that already has a name.
4. PlanWrite pseudocode or the recurrence on paper. Decide the data structures.Starting to code and getting lost halfway.
5. Dry runTrace your plan on the example by hand, then on edge cases: empty, one element, duplicates, already sorted, all equal, maximum size.Off-by-one errors and missed base cases.
6. AnalyseState time and space complexity, and compare with the limit from step 1.Submitting something that is correct but too slow.

Let the input size choose your algorithm

A modern computer does roughly 108 simple operations per second. If the problem tells you the largest n, you can work out which complexity classes are allowed before designing anything.

Largest nComplexity you can affordTypical technique

n ≤ 500O(n³)Triple loops, some DP
n ≤ 5,000O(n²)Double loops, simple DP

n ≤ 107 to 108O(n)One pass, hashing, BFS/DFS

Worked example: two numbers that add to a target

Worked example

Problem. Given a list of n numbers and a target T, decide whether two different positions hold numbers that add up to T. Example: [8, 3, 5, 11], T = 14 → yes (3 + 11).

Brute force (step 2). Check every pair. There are n(n−1)/2 pairs, so O(n²) time, O(1) space.

Better idea (step 3). For each number x, the partner we need is T − x. If we remember the numbers already seen in a set, we can ask "have I seen T − x?" in O(1). One pass: O(n) time, O(n) space. We traded memory for speed.

Remember

Almost every optimisation in this course follows the same story: spot the repeated or wasted work in the brute force, then add a structure (set, heap, tree, table) that removes it.

Recursion: the engine behind half of this course

A recursive function solves a problem by calling itself on a smaller version of the same problem. It needs three ingredients:

  • Base case: the smallest problem, answered directly. Without it the function never stops.
  • Subproblem: a strictly smaller input (n−1, or half the array, or the left subtree).
  • Recursive call: trust that the call returns the correct answer for the smaller input, then use it to build your answer.

Each call waits on the call stack until the call it made returns. Dry run of factorial(4):

MomentCall stack (bottom → top)What happens

Exam trap

Recursion uses memory. factorial(n) is O(n) time and also O(n) space, because n frames sit on the stack at once. Exam questions about "space complexity of a recursive function" are asking about the stack depth.

Strategy families you will meet

Divide and conquer

Split the input into fractions (like halves), solve each recursively, combine. Merge Sort and Quick Sort. Note: factorial is recursive but not divide and conquer, because it shrinks by 1, not by a fraction.

Complete search / backtracking

Try every possibility, building the answer one choice at a time, and undo choices that fail. Slow in theory, but pruning makes it practical.

Dynamic programming

Like complete search, but remember the answer to each subproblem so it is never computed twice.

Greedy

Take the locally best choice and never look back. Fast, but only correct when the problem has a special structure. (Not in your syllabus list, but useful to contrast with DP.)

Added: missing from your notes

Debugging checklist you can use in the exam. Empty input. Single element. Two elements. Duplicates. Already sorted. Reverse sorted. All equal. Negative numbers. The largest allowed n. If your dry run survives all nine, you are probably right.
