Patterns for contests: sorting

Seen in your contests

Contest 1 Q5 asked for Quick Sort in descending order and scored by test. The usual trap: with the last element as pivot, a reverse-sorted or all-equal array makes every partition peel off a single element. That is n² work and n levels of recursion. The fix is a random pivot, a three-way split so equal values are finished at once, and an explicit stack.

Custom order“arrange to make the largest number”, “order by two rules”key= or cmp_to_key
k-th without sorting“median”, “k-th largest”, n largequickselect, expected O(n); or a heap
Count out-of-order pairs“number of swaps”, “pairs i < j with a[i] > a[j]”merge sort that counts while merging
Small value rangevalues up to 10⁶, “frequencies”counting sort, Counter
Minimise the maximum“smallest x such that …”sort, then binary search the answer (stop 14)

In a contest, use Python’s built-in sort (stable, O(n log n)). Write Quick Sort yourself only when the problem tells you to.

The merge step is the only place that changes: when an element of the right half is placed before the remaining left elements, it jumps over every one of them, and each jump is one inversion.

Exam traps

a.sort() returns None (use sorted(a) to keep the original). A comparison function needs cmp_to_key. Touching intervals [1,4] and [4,5] merge when the statement says “overlap or touch” and not when it says “share a point”. Lomuto partition with the last element as pivot is O(n²) on sorted input: say so in a written answer.

Remember

Sort first and the problem often becomes one pass. Out-of-order pairs: count while merging.

A fixed pivot loses to sorted input; a random pivot and a three-way split don’t.

Patterns for contests: BST

Seen in your contests

Contest 1: Q1 minimum in a BST (keep going left), Q6 balanced BST from a binary tree (inorder gives sorted values, then pick the middle), and Q4 Validate BST (40/80, solved after the deadline). The classic trap there: checking only “left child < node < right child” passes the samples and fails the tests, because a node deep in the right subtree must still be larger than the root. Mid-sem Q1 was a plain inorder traversal.

Why the swapped pair shows up as descents: a sorted sequence has none. Swapping two far-apart values creates two descents (take the bigger value of the first and the smaller value of the last); swapping neighbours creates one.

The contest shortcut. In Python there is no built-in balanced BST. When the keys arrive offline, a sorted list with bisect does the same job: insort keeps it sorted and the two functions below give floor and ceiling.

{{code:bisect_bst}}
Exam traps

Duplicates: decide from the statement whether equal keys go left, right or are forbidden, and use the matching strict or non-strict bound. A BST built from sorted input is a linked list of height n: recursion that deep fails in Python, so walk iteratively. Seed the bounds with float('-inf') and float('inf'), not with a guess like 0 or 10⁹.

Remember

Validate with bounds from every ancestor, never with the parent alone.

BST inorder = sorted order; most BST questions are sorted-array questions in disguise.

Patterns for contests: heaps

Seen in your contests

Contest 1: Q2 second minimum of a min-heap (it is the smaller of the root’s two children, min(heap[1], heap[2]), never a scan of everything) and Q3 insertion in O(log n) with heapq forbidden: bubble up by hand (20/40). Mid-sem Q3 was array to min-heap, which is the O(n) build from this stop.

Running median“median after each insertion”max-heap below, min-heap above (this stop)
Rooms and machines“fewest rooms”, “earliest free”min-heap of end times
Best available now“at most k projects”, “always take the biggest”sort by availability, heap of what is unlocked

Exam traps

heapq is a min-heap only: store negatives for a max-heap. Tuples compare left to right, so put the priority first and add an index as a tie-breaker if the second item can’t be compared. “Touching” meetings (end = next start) share a room when the check is <=. Sifting down: compare with both children and swap with the smaller one.

Remember

Heap = the best item now, in O(log n). Sort by when things become available, then pop the best.

No heapq allowed: array + bubble up + sift down, both O(log n).

Seen in your contests

Mid-sem Q4 Generate Parentheses (40/80, late) and Q7 Palindrome Partitioning (0/120) were on a topic you hadn’t studied yet. Q7 is solved at the bottom of this page: one table for “is s[i..j] a palindrome?”, then backtracking that only ever cuts at palindromes.

The same table answers “fewest cuts” without listing anything: min_cuts above is DP, and that switch is the rule: if you only need a count or a best value, and states repeat, stop listing and tabulate.

Choosing by n

n ≤ 10: all orderings (10! ≈ 3.6 million). n ≤ 20: all subsets (2²⁰ ≈ 10⁶), with pruning. n ≤ 40: meet in the middle (2²⁰ per half). Larger: this is not a backtracking problem; look for DP or a greedy.

Exam traps

Append cur[:], not cur: otherwise every saved result is the same list that later gets emptied. Undo exactly what you did. Skip duplicates with i > start (same depth), not i > 0. Pruning before recursing is cheaper than pruning after.

Remember

Choose, recurse, undo. Sort and skip equal siblings. Big items first, skip identical states.

Precompute the yes/no test (palindrome table), then branch only on yes.

Count or best value with repeating states → DP. n ≤ 40 counting → meet in the middle.
