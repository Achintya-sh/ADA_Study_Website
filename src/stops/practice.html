How to practise

Write each answer on paper, the way you would in the exam: a table for every dry run, the recurrence before the answer, the five DP questions before any code. Try for 10 minutes before opening the hint, and 10 more before the solution. Reading a solution feels like understanding; producing it from a blank page is what the exam asks for. Problems follow the order of the stops.

Problem 1: complexity of code

Count the work in three functions

Give the time complexity of each function in Θ notation, with a one-line justification, and the space complexity of c.

Hint

For a, write down how many times the inner loop runs for i = 0, 1, 2, … and add them up. For b, ask how many halvings reach 1. For c, write the recurrence first: how many recursive calls, on what size, plus how much other work?

Solution

a: the inner loop runs n − i times, so the total is n + (n − 1) + … + 1 = n(n + 1)/2. That is Θ(n²). Space O(1).

b: i is halved each pass, so the loop runs about log₂ n times: Θ(log n).

c: T(n) = 2T(n/2) + O(1). Master theorem: a = 2, b = 2, c = log₂ 2 = 1. f(n) = 1 is polynomially smaller than n¹, so the leaves dominate: Θ(n). (Calling c(n // 2) twice doubles the number of calls at every level, so the recursion tree ends with about n leaves. One call would give Θ(log n).) Space: the recursion goes log₂ n levels deep, so O(log n) stack.

Problem 2: recurrences

Solve four recurrences with the Master theorem

For each, state a, b, c = log_b(a), which case applies and the answer. If the theorem does not apply, say why and solve it another way.

(i) T(n) = 4T(n/2) + n   (ii) T(n) = 2T(n/2) + n   (iii) T(n) = T(n/2) + n   (iv) T(n) = 2T(n/2) + n log n

Hint

Compare f(n) with n^c. Smaller by a power of n: leaves win. Equal: every level is equal, multiply by log n. Larger by a power of n (and the regularity check holds): the root wins. Bigger by only a log factor is the gap.

Problem 4: BST operations

Build, traverse, delete

Insert 45, 25, 65, 15, 35, 55, 75, 30 into an empty BST in that order. Draw it, give its height in edges, and write the inorder, preorder and postorder traversals. Then delete 25 and give the new preorder and height.

Hint

Each key walks down from the root: smaller goes left, larger goes right, until an empty spot. 25 has two children, so replace it with its inorder successor: the smallest key in its right subtree.

Solution

Shape: 45 has children 25 and 65; 25 has 15 and 35; 35 has a left child 30; 65 has 55 and 75. The longest root-to-leaf path is 45 → 25 → 35 → 30, so the height is 3.

TraversalBeforeAfter deleting 25

Preorder45 25 15 35 30 65 55 7545 30 15 35 65 55 75
Postorder15 30 35 25 55 75 65 4515 35 30 55 75 65 45

Delete 25: the successor is the minimum of the right subtree (35 → 30), so 30 is copied into 25's node and the old 30 leaf is removed. 35 is left with no children and the height drops to 2. The inorder list is still sorted, which is how you check your answer.

Problem 6: backtracking

Subsets that add up to a target

Write a backtracking function that returns every subset of a list of distinct positive integers whose sum equals a target, using each number at most once. Prune as early as you can. Give the output for nums = [2, 3, 5, 6], target = 8, and the worst-case time.

Hint

Sort the list first. The state is (start index, remaining sum). If the next number is bigger than what remains, every number after it is too, so you can stop the loop.

Solution

Worst case every subset is explored: O(2ⁿ) nodes, O(n · 2ⁿ) counting the copies. The sort costs O(n log n) once and makes the break prune whole branches.

Problem 7: graph traversal

DFS, BFS and shortest paths by hand

An undirected graph has 6 vertices and edges 0–1, 0–2, 1–3, 2–3, 3–4, 4–5. Write the adjacency list (neighbours in increasing order). Starting from 0, give the DFS visit order, the BFS order, the BFS distance of every vertex and the shortest path from 0 to 5. Does the graph have a cycle?

Hint

DFS: go as deep as possible through the smallest unvisited neighbour, back out only when stuck. BFS: process the queue in order, marking each vertex as it is enqueued. Keep a parent array to rebuild the path.

Solution

Adjacency list: 0: [1, 2], 1: [0, 3], 2: [0, 3], 3: [1, 2, 4], 4: [3, 5], 5: [4].

Problem 8: dynamic programming in one dimension

Fewest coins

Coins come in values 1, 3 and 4 (as many of each as you like). Find the fewest coins that make 6. Answer the five DP questions, fill the table, write the code and give its complexity. Why does greedy fail here?

Hint

State: dp[a] = fewest coins that make amount a. Choice: which coin is used last. If the last coin is c, the rest makes a − c.

Solution

State dp[a]: fewest coins for amount a. Choices: the last coin c. Transition: dp[a] = 1 + min over coins c ≤ a of dp[a − c]. Base: dp[0] = 0. Order: a from 1 up to the amount; the answer is dp[6].

a0123456
dp[a]0121122

Answer: 2 coins (3 + 3). Greedy grabs the biggest coin first: 4 + 1 + 1, which is 3 coins. Time O(amount × number of coins), space O(amount).

Hint

Row 0 is all zeros. For each cell: skip item i (copy the cell above) or, if it fits, take it (value plus the cell one row up and w columns left). Trace back from the bottom-right: if a cell differs from the one above, the item was taken.
