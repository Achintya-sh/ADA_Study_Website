Array surgery: swaps, pointers and partitions

Big idea

Quick Sort is one idea, partition, applied recursively. Partition is a pattern you can learn on easier problems first: one pointer reads every element once while a second pointer marks the end of the kept zone, and items that pass a test are swapped into it. Learn the pattern here and Lomuto partition will look familiar.

The swap, and why "in place" matters

a[i], a[j] = a[j], a[i] exchanges two slots in O(1). An algorithm is in place when it rearranges the input using only O(1) extra memory (a few variables), instead of building new lists. Merge sort builds new lists (O(n) extra); Quick Sort and heap sort only swap.

Two pointers from opposite ends

Start one pointer at each end and walk them towards each other. Each step does O(1) work and moves at least one pointer, so the whole thing is O(n).

Compare stop 1's set-based pair sum: O(n) time but O(n) space. When the input is already sorted, two pointers get the same time with no extra memory.

Exam trap

This kind of partition is not stable: evens_first([1, 3, 2]) gives [2, 3, 1], so the odd numbers 1 and 3 swapped order. That is exactly why Quick Sort is not stable.

Three zones: the Dutch national flag

Stop 3 shows that an array of equal values is Quick Sort's worst case: every element goes to the "≤" side. The fix is to split into three zones, less / equal / greater, so all the equal values are finished in one pass.

Teacher's note

The three-way version goes slightly past your syllabus, but it is the clearest way to see why duplicates hurt two-way Quick Sort, and it is a favourite "improve this algorithm" question.

Remember
  • In place = O(1) extra memory, just swaps.
  • Two pointers from both ends: O(n), needs a reason to move one pointer each step (often sortedness).
  • Reader–writer partition: k marks the end of the kept zone; grow k, then swap. Lomuto is this with test "≤ pivot".
  • These partitions are not stable.
