Bridge to stop 5

Complete trees by numbers, and the priority queue idea

Big idea

A heap glues two separate ideas together: a promise (the priority queue: always hand out the most important item next) and a shape (the complete binary tree, which packs perfectly into an array with simple index arithmetic). Learn each one on its own and stop 5 is just the glue.

What versus how: abstract data types

An abstract data type (ADT) lists operations and what they promise, nothing about memory. A data structure is one way to keep those promises. A stack is an ADT (push, pop, last in first out); a Python list is one structure that implements it.

The priority queue ADT promises: insert(x), peek_max(), extract_max(). Several structures can keep that promise, at very different costs:

Unsorted listO(1) appendO(n) scanO(n) scan + remove

Each of the first three is fast at something and slow at something else. The heap is never the fastest at any single operation, but it is never slow, and its height is guaranteed to be log n because of its shape.

Numbering a complete tree level by level

A complete binary tree fills every level left to right with no gaps (only the last level may be partly full). Number its nodes in that reading order starting from 0, and the numbers fall into a pattern:

  • Level d starts at index 2ᵈ − 1 and holds 2ᵈ slots (1, 2, 4, 8, …).
  • Take node i, the j-th node on level d, so i = 2ᵈ − 1 + j. Its left child is the 2j-th node on level d + 1, at index 2ᵈ⁺¹ − 1 + 2j = 2(2ᵈ − 1 + j) + 1 = 2i + 1.
  • So the right child is 2i + 2, and going back up, the parent is (i − 1) // 2.

No pointers are needed: the array position is the tree position. This only works because there are no gaps, which is why a heap insists on being complete.

Added: missing from your notes

0-based versus 1-based. CLRS numbers from 1: children 2i and 2i + 1, parent ⌊i/2⌋. Python lists start at 0: children 2i + 1 and 2i + 2, parent (i − 1) // 2. Mixing the two is the classic heap bug. In an exam, say which convention you are using.

Remember
  • ADT = the promise; data structure = how it's kept. A heap implements a priority queue.
  • 0-based: children 2i + 1, 2i + 2; parent (i − 1) // 2.
  • n nodes: height ⌊log₂ n⌋, ⌈n/2⌉ leaves, last internal node n // 2 − 1.
