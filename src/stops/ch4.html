Binary trees and Binary Search Trees

Big idea

Binary search brings an "ignore half the data" trick to dynamic data. Learn the one rule, and search, insert and delete all follow.

Binary trees from scratch

Why trees at all?

An array or list is linear: items are in a single row, so finding something means walking along it. Real data is often hierarchical: a folder holds folders, a company has managers and reports, a decision leads to further decisions. A tree stores that shape directly, and (as the next chapters show) a well-shaped tree lets you reach any item in about log n steps instead of n.

Definition

Remember

A binary tree is either empty, or a root node together with a left subtree and a right subtree, each of which is itself a binary tree.

That definition is recursive, and this is not an accident: almost every tree algorithm is a recursive function that handles "the empty tree" (base case) and "the root plus two smaller trees" (recursive case).

The rules of a binary tree

  1. One root. There is exactly one topmost node, and it has no parent. (A tree may be empty.)
  2. One parent each. Every other node has exactly one parent: the node directly above it.
  3. At most two children, and they are labelled. A node has a left child and/or a right child, each possibly missing. "Only a left child" and "only a right child" are different trees.
  4. No cycles, and connected. From the root there is exactly one path down to every node. You can never walk around in a loop.
  5. No rule about the values. A plain binary tree may hold any values in any arrangement. Extra ordering rules are what make a BST (this chapter) or a heap (next chapter).
Exam trap

Students often mix up the rules. "Parent greater than child" is the heap rule. "Left smaller than node, right larger" is the BST rule. A plain binary tree has neither. Keep the three apart: shape rules (at most 2 children; complete) and value rules (BST order; heap order).

What a node looks like in code

A leaf is a node whose left and right are both None. The whole tree is referred to by a single variable: the root. If you hold the root you can reach everything.

Counting facts you can quote in an exam

FactWhy it is true
A tree with n nodes has n − 1 edges.Every node except the root has exactly one edge going up to its parent.
Level i (root = level 0) holds at most 2i nodes.Each node can have at most 2 children, so every level can at most double the one above.
A tree of height h has at most 2h+1 − 1 nodes.1 + 2 + 4 + … + 2h (a geometric sum). Example: height 2 → 7 nodes.
A tree with n nodes has height at least ⌈log₂(n+1)⌉ − 1, and at most n − 1.Best case: levels packed full. Worst case: a single chain.
A full binary tree has leaves = internal nodes + 1.Count edges both ways: n − 1 = 2 × (internal nodes), with n = internal + leaves.
A binary tree with n nodes has n + 1 empty (None) child slots.2n slots in total, and n − 1 of them are used by edges.

The heart of the whole chapter: height controls speed. A packed tree of a million nodes has height about 20, so a path from the root to anywhere is about 20 steps. A chain of a million nodes has height 999,999. Same nodes, wildly different performance.

Shapes of binary trees

Two ways to store a binary tree

Pointer nodes

Each node is an object with left and right pointers (as above). Works for any shape. Used for BSTs.

Array

Store level by level; the children of index i live at 2i + 1 and 2i + 2, and the parent at (i − 1) // 2. No pointers needed, but gaps would waste space, so it is used only for complete trees, which is exactly what heaps are.

Three small recursive helpers

Every tree function follows one pattern: handle None, then combine the answers for the left and right subtrees. Learn this and the rest of the chapter becomes easy.

The three depth-first traversals

A traversal visits every node once. The three classic orders differ only in when you handle the node relative to its subtrees. A handy mnemonic: the name says where the node goes.

TraversalOrderResult
Preordernode, left, right1 2 4 7 3 6
Inorderleft, node, right4 2 7 1 3 6
Postorderleft, right, node4 7 2 6 3 1
Level order (BFS)row by row1 2 3 4 7 6
Remember

Traversals are all forms of DFS (go deep, then backtrack). Level order is BFS. You will meet both again on graphs in chapter 8.

How to carry out a traversal by hand

Each rule is the same recursive recipe with the "visit the node" step placed at a different moment:

  • Preorder (NLR): visit the node, then do the left subtree, then the right subtree.
  • Inorder (LNR): do the left subtree, then visit the node, then the right subtree.
  • Postorder (LRN): do the left subtree, then the right subtree, then visit the node.
Teacher's note

The flag trick. Walk once around the outside of the tree, starting at the left of the root and keeping the tree on your left. Preorder writes a node when you pass its left side (first time you meet it). Inorder writes it when you pass underneath it. Postorder writes it when you pass its right side (the last time you see it).

Edit the tree below (level order, # for a missing child) and step through each traversal. Watch the call stack: every pending call is a node still waiting for its subtrees to finish. When a call hits None it returns at once; that is the base case.

The BST rule

Remember

For every node x: all values in x's left subtree are smaller than x, and all values in x's right subtree are larger than x. The rule must hold at every node, not just the root.

  • Duplicates: either forbid them, or always send them the same way (say, right). Never mix. (CLRS writes left ≤ node ≤ right; your notes use strict < and >. Say which convention you use.)
  • Why it helps: at a node, one comparison tells you which entire half of the remaining tree can be ignored. This is binary search, but on a linked structure that supports cheap inserts and deletes (unlike a sorted array, where insert is O(n) because of shifting).
  • Superpower: an inorder traversal of a BST prints keys in sorted order in Θ(n). Because left < node < right is exactly the inorder visit order.
Exam trap

A tree where each node is merely bigger than its left child and smaller than its right child is not necessarily a BST. Example: root 10, left child 5, and 5's right child 15. Locally fine (15 > 5), but 15 is in the left subtree of 10 and must be less than 10. We come back to this in "validate a BST" below.

The BST rules, stated precisely

  1. A BST is a binary tree (at most two children per node).
  2. For every node x: every key in x's left subtree is smaller than x's key, and every key in x's right subtree is larger.
  3. The rule is recursive: x's left and right subtrees are themselves BSTs.
  4. Decide one duplicate policy: reject duplicates, or always send an equal key to the same side.

Operations

Search

Start at the root. If the target is smaller, go left; larger, go right; equal, found; fell off the tree (None), not present. Each step discards a whole subtree.

Insert

Walk exactly as in search until you reach an empty spot. Put the new node there. A new key always becomes a leaf.

Exam trap

The line node.left = insert(node.left, value) must assign the return value. If you write just insert(node.left, value), the new node is created but never linked to its parent and is lost.

Minimum, maximum, successor

  • Minimum: keep going left until there is no left child. Maximum: keep going right.
  • Inorder successor of x (the next larger key): if x has a right subtree, it is the minimum of that subtree. Otherwise climb up until you arrive from a left child; that ancestor is the successor.

Delete: the three cases

This is the operation examiners love. Find the node z, then look at how many children it has.

CaseWhat to doWhy it is safe
1. Leaf (no children)Remove it (set the parent's pointer to None).Nothing hangs below it.
2. One childReplace z by its only child (the parent now points to that child).The whole child subtree was on the correct side of the parent, so it stays valid.
3. Two childrenFind z's inorder successor y = minimum of z's right subtree. Copy y's value into z. Then delete y from the right subtree (y has no left child, so that is case 1 or 2).y is the smallest key larger than z, so it is greater than everything on the left and smaller than everything else on the right. (Symmetric alternative: use the predecessor, the maximum of the left subtree.)
Added: missing from your notes

CLRS's version does not copy values; it relinks nodes with a helper called TRANSPLANT(u, v) that replaces the subtree rooted at u by the subtree rooted at v. Case 3 there: if the successor y is z's right child, replace z by y directly; otherwise first replace y by y's right child, then replace z by y. Copying values (above) is simpler to write; relinking is better when other code holds pointers to nodes.

Worked trace: build, then delete

Worked example

Insert 50, 30, 70, 20, 40, 60, 80 in that order. 50 becomes the root. 30 < 50 → left. 70 → right. 20 → left of 50, then left of 30. 40 → left of 50, right of 30. 60 → right of 50, left of 70. 80 → right of 70. A perfectly balanced tree of height 2; inorder gives 20 30 40 50 60 70 80.

Delete 50 (root, two children): successor = minimum of the right subtree = 60. Copy 60 into the root, then delete the original 60 (a leaf). Inorder now: 20 30 40 60 70 80. Delete 30 next (two children 20 and 40): successor = 40 (minimum of its right subtree). Copy, remove old 40. Try it on the lab.

Cost: it all depends on the height h

Search, insert, delete, min, max, successor all follow a single root-to-leaf path, so each costs O(h).

Exam trap

A plain BST is not self-balancing. "BST operations are O(log n)" is only true for balanced trees. Insert 1, 2, 3, 4, 5 in order in the lab and watch it collapse into a line.

Added: missing from your notes

Self-balancing trees (AVL, Red-Black) fix this: after each insert or delete they use rotations to keep the height O(log n) always, so worst-case operations are O(log n). AVL keeps the heights of the left and right subtrees of every node within 1 of each other. Not needed for this exam beyond knowing why they exist.

Problem solving with BSTs

Almost every BST problem uses one of three ideas: (a) inorder = sorted; (b) use the rule to discard half the tree; (c) pass down bounds that every node in a subtree must respect.

1. Validate a BST

Passing bounds down is the key. Each node must lie strictly between the largest ancestor you turned right at and the smallest ancestor you turned left at.

2. k-th smallest element

Inorder visits keys in increasing order, so stop at the k-th visit. O(h + k).

3. Lowest common ancestor (LCA) of two keys

If both keys are smaller than the current node, the LCA is on the left; if both larger, on the right; otherwise the current node is where they split, so it is the LCA. O(h).

4. Sorted array to balanced BST

Take the middle element as the root so both sides have nearly equal size, then recurse on each half. Height = O(log n).

5. Range sum: add all keys between L and R

Prune: if a node is below L, its whole left subtree is too small, so skip it. Likewise above R.

Added: missing from your notes

More patterns to know: floor and ceiling of a key (walk like search and remember the last candidate), convert BST to a sorted linked list (inorder), count nodes in range, two-sum in a BST (inorder to array, then two pointers), recover a BST with two swapped nodes (inorder shows two inversions), find height, check if two trees are identical.

Try the tree 5 → (left 1, right 6 → (left 3, right 7)). is_bst_wrong says True; is_bst says False, because 3 sits in the right subtree of 5 and is smaller than 5.

Why the swapped pair shows up as descents: a sorted sequence has none. Swapping two far-apart values creates two descents (take the bigger value of the first and the smaller value of the last); swapping neighbours creates one.

The contest shortcut. In Python there is no built-in balanced BST. When the keys arrive offline, a sorted list with bisect does the same job: insort keeps it sorted and the two functions below give floor and ceiling.

Exam traps

Duplicates: decide from the statement whether equal keys go left, right or are forbidden, and use the matching strict or non-strict bound. A BST built from sorted input is a linked list of height n: recursion that deep fails in Python, so walk iteratively. Seed the bounds with float('-inf') and float('inf'), not with a guess like 0 or 10⁹.

Remember

Validate with bounds from every ancestor, never with the parent alone.

BST inorder = sorted order; most BST questions are sorted-array questions in disguise.
