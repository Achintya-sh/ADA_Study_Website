Monotonic stacks and queues

Big idea

A monotonic stack keeps its contents in sorted order by popping everything that can no longer matter before pushing the new item. That one rule turns “for each element, find the nearest bigger/smaller one” from O(n²) into O(n): every element is pushed once and popped once. Your course outline lists monotonic stacks as a feature; this stop is where they live. The monotonic deque is the same idea with the front also expiring, for sliding windows.

Words in the statementTool

“largest rectangle”, “widest range where this is the minimum”the popped element’s left and right boundaries

“smallest number / lexicographically smallest after removing k”pop while the top is bigger than the new item and removals remain
“maximum of every window of size k”monotonic deque
“trapped water”two pointers, or a stack of walls

The template: next greater element

The stack holds indices whose answer is still unknown, with decreasing values. A new value that beats the top is the answer for everything it beats.

Dry run on [2, 1, 2, 4, 3]: push 0; 1 doesn’t beat 2, push 1; the second 2 beats index 1 (answer 2), not index 0 (equal), push 2; 4 beats indices 2 and 0 (answer 3), push 3; 3 beats nothing, push 4. Result [3, 2, 3, −1, −1]. Strict versus non-strict comparison (< versus <=) is the one decision that changes with the wording “greater” or “greater or equal”.

Histogram: each bar, as the shortest bar of a rectangle

Contribution counting, and the tie-break that avoids double counting

Sum of the minimum over all subarrays: element i is the minimum of (distance to the previous smaller) × (distance to the next smaller) subarrays. With equal values both sides would count the same subarray, so make one side strict and the other non-strict.

Exam traps

Store indices, not values, when you need distances. Decide strict versus non-strict from the statement’s wording about equal values. Flush the stack at the end (a sentinel 0 in the histogram) or the last bars never get an answer. Pop in a while, not an if. Each element is pushed once and popped once, so the whole thing is O(n) even though there’s a loop inside a loop.

Remember

Pop what can’t matter any more, then push. Next/previous greater/smaller in O(n).

Min or max over all subarrays: each element’s contribution = left span × right span, one side strict.

Sliding window maximum: a deque whose front expires.
