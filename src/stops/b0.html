Tracing code by hand

Big idea

Before you can design an algorithm you have to be able to run one in your head. A trace table records every variable after every step; a call stack records every function call that hasn't finished yet. Both are exactly what "dry run" questions ask for, and stop 1 starts writing recursive code straight away.

The trace table

One column per variable, one row per step (usually one loop iteration). Fill it in strictly in order; never skip ahead to what you "know" the answer is.

Loop invariants: what stays true every lap

A loop invariant is a sentence about the variables that is true every time the loop is about to go round again. For find_max: "best is the largest value in a[0..i]". You check three things, exactly as CLRS does:

CheckQuestionFor find_max
InitialisationIs it true before the first iteration?best = a[0] is the largest of a[0..0].
MaintenanceIf it is true before an iteration, is it still true after?If a[i] beats the old maximum it becomes best; otherwise best stays the largest.
TerminationWhen the loop stops, what does it tell you?i reached n − 1, so best is the largest of the whole array.
Teacher's note

Invariants are how the rest of the course explains its algorithms. Quick Sort's partition keeps "everything in a[lo..k] is ≤ pivot". Sift down keeps "the heap rule holds everywhere except at i". BFS keeps "the queue holds vertices in order of distance". When an explanation in a later stop says "at every step…", it is stating an invariant.

Tracing recursion: frames and the way back

Every call gets its own frame: its own copy of the parameters and local variables. When a function calls itself, the caller pauses on that line and waits. The lines after the call run later, on the way back, once the inner call returns. Research on how students learn recursion finds that this "backward flow" is one of the most common sticking points, so trace it deliberately.

returni=0rest = 6, return 4 + 6 = 10

The deepest moment has n + 1 frames on the stack, which is why recursion over n items costs O(n) space even when it allocates nothing else.

Exam trap

Each frame has its own variables: the i in one call is not the i in another. And a recursive function whose base case is missing or unreachable doesn't loop forever quietly: Python stops it with RecursionError after about 1,000 nested calls (the default limit).

Remember
  • Trace table: one column per variable, one row per step, filled strictly in order.
  • Invariant: true before the loop, kept by every lap, useful when the loop ends.
  • Recursion: one frame per call; the caller pauses; code after the call runs on the way back.
  • Deepest stack = space cost of the recursion.
