Graphs II: order, cycles, weights

Big idea

Week 11 of the course: shortest paths and spanning trees. Every tool below is BFS or DFS with one thing changed. Topological order (Kahn or DFS) puts a DAG’s vertices in an order where every edge points forward, and it detects cycles. Dijkstra is BFS with a heap, for non-negative weights. 0-1 BFS swaps the heap for a deque. Bellman–Ford survives negative edges and finds negative cycles. Floyd–Warshall does all pairs when V is small. Union-find answers “already connected?” as edges arrive, which is all Kruskal’s minimum spanning tree needs. Your syllabus marks the MST optional; the learning outcomes still list it, so it is covered in full here.

1. Order without cycles: topological sort

If a graph has no directed cycle (a DAG), its vertices can be listed so that every edge goes from earlier to later. “Course b before course a”, “build step 1 before step 2”, and “this cell leads to a bigger cell” are all DAGs. There are two standard ways to get the order, and both detect a cycle for free.

Kahn’s algorithm (peeling). A vertex that nothing points to can safely go first. Remove it, lower the in-degree of everything it points to, repeat. If some vertices never reach in-degree 0, they lie on or behind a cycle.

DFS version. Run DFS and list vertices in reverse finishing order: a vertex finishes only after everything it points to has finished, so it ends up before them in the reversed list. Three colours (unseen, on the current path, finished) detect cycles: meeting a vertex that is on the current path means a back edge, which means a cycle. This version is iterative, so a 200,000-long chain cannot hit Python’s recursion limit.

Course Schedule. LC 207 only asks whether an order exists; LC 210 asks for one. Note the direction: [a, b] means b comes before a, so the edge is b → a.

DP over a DAG

In a DAG the topological order is a valid order to fill a DP table: by the time you reach u, every path into u has already been accounted for. So shortest and longest paths, even with negative weights, need no heap: process vertices in topological order and relax their out-edges once. Longest path is NP-hard on general graphs but easy here, because there are no cycles to loop around. Counting paths is the same loop with + in place of min.

Contest problems that are secretly DAGs

LC 329 Longest Increasing Path in a Matrix. Draw an edge from each cell to every bigger neighbour: a DAG, because values strictly increase. The longest path is the number of Kahn layers. The usual memoised DFS recurses up to 40,000 levels on a 200×200 grid, which exceeds Python’s default recursion limit of 1,000; peeling avoids recursion entirely.

LC 1857 Largest Color Value in a Directed Graph. Keep, for every vertex, the best count of each of the 26 colours on any path ending there, and push it forward in topological order. If Kahn does not reach every vertex there is a cycle and the answer is −1. A self-loop never reaches in-degree 0, so it is caught the same way.

2. Dijkstra: BFS with a heap

BFS finds the fewest edges. With weights a longer route can be lighter: in the lab graph, 0 → 1 directly costs 4, but 0 → 2 → 1 costs 1 + 2 = 3. Dijkstra’s rule: always finish the closest unfinished vertex next. Python’s heapq is a min-heap of tuples, so a heap of (distance, vertex) pops the closest first.

Cost. Each vertex is expanded once and each edge pushes at most one entry, so there are at most E pushes and pops, each O(log E) = O(log V): O((V + E) log V). For an undirected graph add each edge in both directions.

Why it is correct, and why negative edges break it

Claim: when (d, u) is popped and is not stale, d is the true shortest distance to u. Any other route to u must leave the set of finished vertices through some edge into an unfinished vertex x. That x is still in the heap with a value of at least d (u was the smallest), and the rest of the route can only add non-negative weight, so it cannot come in below d. The proof uses exactly one assumption: extending a path never makes it cheaper.

A negative edge breaks that assumption. On 0→1 (2), 0→2 (3), 2→1 (−2) the textbook version below finalises vertex 1 at distance 2 and never looks again, although 0 → 2 → 1 costs 1. It returns 2, which is wrong:

The stale-check template above would, on this tiny graph, expand vertex 1 a second time and recover the answer 1. Do not rely on that: re-expanding vertices voids the O((V + E) log V) bound (on adversarial graphs it can take exponential time), and a negative cycle makes it loop forever. With negative edges use Bellman–Ford.

Dijkstra on grids, and “minimise the maximum”

A grid is a graph whose vertices are cells and whose edges join neighbours (stop 6.5). Dijkstra works whenever the cost of a path is built so that extending it never lowers it, and that includes more than sums. In LC 1631 Path With Minimum Effort the cost of a path is its largest height difference, so replace d + w by max(d, w). LC 778 Swim in Rising Water is the same with the cell height as the cost. LC 1514 Path With Maximum Probability maximises a product of numbers at most 1: store negated probabilities in the min-heap.

For “minimise the maximum” there is a second solution that is often shorter to write: binary search the answer, with a plain BFS answering “can I get there if no step may exceed x?”. It costs O(cells · log(range)).

3. When the weights are 0 or 1

A free edge keeps you on the same level, so its end goes to the front of the deque; a cost-1 edge goes to the back. The deque always holds at most two distance values, in order, so no heap is needed: O(V + E).

4. An extra rule: free passes

“Up to k edges on your path cost nothing” is the node-is-a-state idea with weights: the node is (vertex, passes used), and each edge can be taken normally or with a pass.

5. Negative edges: Bellman–Ford, and all pairs: Floyd–Warshall

Why V − 1 rounds are enough. If there is no negative cycle, some shortest path to every vertex is simple (a repeated vertex would mean a cycle of weight ≥ 0 that can be cut out), so it has at most V − 1 edges. One round relaxes every edge once. After round r, the distance of every vertex is at most the cost of its best path with at most r edges, because the last edge of such a path is relaxed in round r. So after V − 1 rounds all distances are final. Negative cycle: run one more round; if anything still improves, a reachable negative cycle exists and shortest distances are undefined.

“At most k edges”: LC 787

“At most k stops” means at most k + 1 edges, so run exactly k + 1 rounds. Here the in-place shortcut is a bug: it could let a round use two edges. Read from the old row and write to a copy, so each round adds exactly one edge:

Floyd–Warshall: all pairs

Let dk[i][j] be the shortest i → j distance using only vertices 0..k−1 as intermediate stops. Either the best route avoids k, or it goes i → k → j: dk+1[i][j] = min(dk[i][j], dk[i][k] + dk[k][j]). The k loop must be outermost because the table must be complete for k − 1 before k is allowed. Time O(V³), space O(V²), so only for V up to a few hundred. LC 1334 is the standard use: count the cities within the threshold from every city.

6. Minimum spanning trees

A spanning tree of a connected graph uses V − 1 edges and connects every vertex with no cycle. A minimum spanning tree (MST) is one of least total weight. Think of laying cable to connect every town for the lowest cost.

Two facts justify every MST algorithm:

  • Cut property. Split the vertices into two non-empty groups. A lightest edge crossing between the groups belongs to some MST (to every MST if it is the unique lightest crossing edge).
  • Cycle property. On any cycle, an edge that is strictly heavier than all the others on that cycle belongs to no MST.

Why the cut property holds: take any MST without that edge e. Adding e creates a cycle, which must cross the cut a second time through some edge f. Swapping f for e keeps a spanning tree and its weight does not go up, because e was a lightest crossing edge.

Kruskal: sort the edges, keep the ones that join two pieces

Process edges from lightest to heaviest. An edge is kept if its endpoints are in different components (union-find answers this), and skipped if it would close a cycle. When Kruskal keeps edge e joining components A and B, e is the lightest edge leaving A (anything lighter was processed earlier and either joined things or lay inside a component), so the cut property says keeping it is safe. The union-find below uses path halving and union by size, which together make each operation almost constant (inverse Ackermann; see the appendix stop). Cost: sorting dominates, O(E log E) = O(E log V).

Prim: grow one tree, always take the cheapest edge leaving it

Start anywhere. Repeatedly add the lightest edge from the tree to a vertex outside it; the tree versus the rest is a cut, so the cut property applies every time. It is Dijkstra with one change: the heap key is the single edge entering the tree, not the distance from the source. Entries for vertices already in the tree are stale and skipped, as in Dijkstra.

MST problems in contests

LC 1584 Min Cost to Connect All Points is a complete graph with Manhattan distances, so use heap-free Prim, O(n²). LC 684 Redundant Connection: add edges in input order; the first one whose endpoints are already connected closes the cycle. LC 1135 Connecting Cities is plain Kruskal with a −1 answer if fewer than V − 1 edges are kept.

LC 1489 Critical and Pseudo-Critical Edges (harder). An edge is critical if every MST uses it: banning it makes the best tree heavier or impossible. It is pseudo-critical if some MST uses it but not all: forcing it in still gives the optimal weight. With n ≤ 100 and m ≤ 200, running Kruskal about 2m times is fast enough.

7. Union-find, and running time backwards

Reverse-time trick (CF 722C). DSU can merge but not split. When a problem removes things one by one and asks for something after each removal, run time backwards: start empty and add them in reverse order.

8. Choosing the right graph algorithm

Ask these in order and stop at the first yes.

#Question about the problemUse
1Is there an order or dependency (“before”, “prerequisite”, “builds on”)?Topological sort (Kahn); DP in that order if you need a best value. A cycle means no answer.
2Do you need to connect everything at least total cost, rather than reach one target?MST: Kruskal, or heap-free Prim if the graph is dense.
3Do you only ask “are these connected?” as edges arrive, or merge groups?Union-find.
4Is the cost the largest edge on the path, or a “minimise the maximum”?Dijkstra with max, binary search plus BFS, or Kruskal.
5All edges cost the same (or you count edges)?BFS (multi-source if there are several starts).
6All weights are 0 or 1?0-1 BFS.
7Are some weights negative?DAG: topological DP. Otherwise Bellman–Ford (and it spots negative cycles).
8“At most k edges / stops”?Bellman–Ford for exactly k rounds, or Dijkstra on (node, steps used).
9An extra rule (passes, parity, keys, time)?Make the state (node, extra), then BFS or Dijkstra on states.
10Shortest paths between all pairs and V ≤ about 400?Floyd–Warshall.
11Weights are non-negative and you want from one source?Dijkstra.

The constraints help too: V ≤ 400 allows O(V³); V, E ≤ 10⁵ needs O(E log V) or better; V ≤ 20 points to a bitmask over the vertices.

Exam traps

In BFS you mark a vertex when you push it; in Dijkstra a vertex is final only when popped, because a cheaper route can still arrive (see the spot-the-bug drill). Dijkstra needs “extending a path never makes it cheaper”: negative edges violate it. Undirected graphs need both directions in the adjacency list. Kahn returning fewer than n vertices means a cycle, not a bug. Course prerequisites [a, b] point b → a. A recursive DFS on 10⁵ levels will crash in Python. Floyd–Warshall needs the k loop outermost. For “at most k edges” read the old row. Prim and Kruskal can return different trees of equal weight when weights tie.

Remember

Kahn: queue every in-degree-0 vertex, peel, repeat. Fewer than n out → cycle. DFS: reverse finishing order; an edge into a vertex on the current path → cycle.

Dijkstra: pop smallest, skip stale, relax; final on pop. No negative edges. “Max of the path” → max(d, w).

Weights 0/1 → deque. Negative → Bellman–Ford (V − 1 rounds, one more to detect a cycle). At most k edges → k + 1 rounds on a copy. Extra rule → states. All pairs, small V → Floyd, k outermost.

MST: cut property (lightest crossing edge is safe), cycle property (heaviest on a cycle is out). Kruskal: sort edges, keep what union() accepts, V − 1 kept or disconnected. Prim: grow a tree with a heap, or O(V²) on dense graphs.
